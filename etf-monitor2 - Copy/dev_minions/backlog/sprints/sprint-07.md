## Goal

Arbitrary ETFs either work or fail visibly and correctly (roadmap, Sprint 7). EPIC-07 "Done when": "adding an arbitrary BVB ETF either works or degrades visibly and correctly."

Concretely:
- **The second report format (ICBETNETF).** Requirements §3 says its administrator is different (Intercapital), it uses "VAN" instead of "VUAN", and its report is downloaded through "a submit button, not a direct link". It also says "we were not able to fully confirm its structure yet".
  - US-029 finds out how that download works.
  - If it can be done deterministically, US-029 ships the access code and a second adapter.
  - If it cannot, US-029 ships a documented fallback: ICBETNETF stays "extraction unavailable". Nothing is guessed.
- **The no-adapter path, end to end** (section 3). An ETF with no matching adapter "is still shown in the list (with a link to its report), but automatic extraction is marked 'unavailable' — until a new adapter is added for that format". Today these ETFs are listed with the marker but **without** the link (US-016 out of scope). US-030 adds the link. It also proves the whole path for both add paths, form and chat, and the recovery once an adapter exists.
- **Proof on the real deployment** (US-031):
  - an offline end-to-end test of the whole pipeline;
  - a read-only smoke script the user can point at the deployment;
  - a runbook of every live check.
  It also closes the last small test debts the roadmap carries.

## Why this order

- **US-029 first.** What it finds shapes the other two stories:
  - whether a report can be reachable without a direct PDF URL (decision 4);
  - how many requests one ETF can cost the daily run (decision 8);
  - whether a second adapter exists, which is when the column-label rule must be reconciled (decision 3).
  It is also the story most likely to stop on a live step. Starting it first means a block is known early.
- **US-030 does not depend on US-029.** If US-029 is Blocked on live access, US-030 still runs. It works on the no-adapter path that exists today, and US-029's fallback branch lands on that same path. The per-ETF request bound is one shared constant, so whichever story lands second keeps the budget test honest (US-029 AC9, US-030 AC7).
- **US-031 last.** It verifies the system both stories leave behind, so it depends on both.

## Manual QA the user must perform in this sprint

Everything below touches your Neon database, your Vercel project or your accounts, so it is yours. The Codex QA loop checks the offline and locally served parts, and may do live **read-only** bvb.ro reads (AGENTS.md). Order matters in steps 1–2.

1. **Migration first (US-030).** Before you deploy the Sprint 7 code, run `DATABASE_URL=<neon-url> pnpm db:migrate` locally. In the Neon SQL editor, `select * from etf_report_links;` returns an empty table, not an error. Then commit, push and wait for the Production deployment. If you deploy first, the home page shows its translated error until the migration runs.
2. **Catalogue (US-029, only if it shipped an adapter).** Run `DATABASE_URL=<neon-url> pnpm db:seed` (safe to re-run, US-020 AC1). `select * from field_catalog where adapter_key = '<new key>';` lists the new adapter's fields with RO/EN labels.
3. **ICBETNETF (US-029).** In `/admin/etfs`, add `ICBETNETF`, or re-detect it if you already added it in Sprint 6.
   - ADAPTER branch: the adapter shown is the new key. Track one or two fields in its fields page. After the next daily run (or Vercel → project → Settings → Cron Jobs → Run), the home table shows its values. Open the report (link, or the bvb.ro page per decision 4) and compare every value and the date by eye.
   - FALLBACK branch: the adapter is "none". The row shows "extraction unavailable". Read `spikes/icbetnetf/FINDINGS.md` (path per the plan) for why, and what would unblock it.
4. **An arbitrary ETF with no adapter (US-030).** From bvb.ro → FundUnits, pick a fund unit that is not monitored. Add it once through `/admin/etfs` and once (after removing it) through `/chat`. Each time:
   - the admin list shows adapter "none";
   - the home row shows "extraction unavailable" and its symbol opens that fund's newest report PDF (decision 5), or is plain text if bvb.ro lists none (decision 4);
   - `/etf/<SYMBOL>` shows the marker (decision 10);
   - after the next run, `/admin/operations` shows the run as partial with a translated "no adapter" line for it.
   Remove it at the end.
5. **Deployment smoke (US-031).** Run the smoke command from the US-031 QA checklist against `https://etf-monitor2.vercel.app`. It exits 0 and prints one line per page, and no page body.
6. **Full runbook (US-031).** Work through `verification/US-031-qa.md`:
   - one chat command per provider (sprint-06 forward note);
   - RO/EN on every page;
   - `/health`;
   - a **scheduled** (not manual) cron run visible in `/admin/operations` (still open since Sprint 3);
   - Vercel → Logs show no API key, `CRON_SECRET` or `DATABASE_URL` value;
   - the function duration of the cron run is well under 60 s.
7. **PO confirmation.** Every story in this sprint was drafted by an agent. Confirm or correct the acceptance criteria, and answer the PRODUCT items above (#4, #5, #10, #12; #9 is already on your list).
