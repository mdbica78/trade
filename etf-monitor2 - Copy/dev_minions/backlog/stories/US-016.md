# US-016 — Home table with configurable columns and PDF links
> Detailed by agent (story-planner), 2026-09-25 — PO to confirm at demo.

**Sprint:** 4 · **Epic:** EPIC-04 · **Depends on:** US-004, US-005, US-012, US-014
**Suggested model / thinking:** strong model, high thinking. Complex (new read layer tested on PGlite, shared formatters used by the whole sprint, 11 ACs), so it is planned by `story-planner`.

## Context

FR7 defines the home page: "A table listing all currently monitored ETFs. Each row: ETF symbol, **clickable**, linking directly to the most recent PDF report; dynamic columns = the parameters the user has chosen to see (not fixed — configurable); for each parameter: today's value + the difference vs. the previous day (both absolute and percentage)." The difference is US-017. This story builds everything else.

What exists:
- `app/page.tsx` is still the Sprint 1 placeholder (`Home.intro`).
- The data model has everything the table needs. `etfs.is_active` is "soft removal from monitoring". `tracked_fields.display_order` is the "column order on the home table". `field_catalog.label_ro`/`label_en` are the UI labels. `reports.source_url` is the "direct PDF link, shown in the UI (FR7)". `report_values.numeric_value` is the canonical number (`numeric`, no separators; the adapter strips the source's thousands commas and keeps the decimals as printed, e.g. `8640000.00`).
- Sprint 3 writes `ok` rows (complete) and `parse_error` rows (incomplete, possibly with some values) (US-012, US-014). An ETF with no adapter has no `reports` row at all (US-014 decision 1).
- DEC-007 fixes number display: no thousands separator, comma decimal mark in `ro`, dot in `en`. No shared formatter exists yet (US-004 deferred it).
- Sprint 1 audit N2: set `timeZone` in `i18n/request.ts` before the first story that formats dates. This story shows report dates.
- Sprint 3 reads/writes go through `db.execute(sql…)` statements and a `BatchRunner` (`lib/ingestion/store.ts`). In tests, PGlite runs the same statements (`test/helpers/pglite.ts`).

## Task

1. **Read model**, e.g. `lib/monitoring/home.ts`. One function returns the view model for the table. Build its SQL with `db.execute(sql…)` and run it through an injected `BatchRunner`, like `lib/ingestion/load-etfs.ts`, so the PGlite tests execute the shipped statements:
   - **rows**: every ETF with `is_active = true`, ordered by symbol. Each row has `symbol`, `adapterAvailable`, `latestPdfUrl`, `valueDate` and one cell per column;
   - **columns**: the union rule of decision 3. Each column has `fieldKey`, `labelRo`, `labelEn`;
   - **`latestPdfUrl`**: `source_url` of the ETF's newest `reports` row (by `report_date`) that has a non-null `source_url`, whatever its status. FR7 asks for "the most recent PDF report", not the most recent readable one;
   - **values**: from the ETF's newest `ok` report (decisions 1 and 2). `valueDate` is that report's `report_date`. A cell is `{ tracked: false }` for a field the ETF does not track, and `{ tracked: true, value: string | null }` otherwise. `value` is the stored `numeric_value` string, or `null` if that report has no row for the field. A value is never taken from an older report;
   - **`adapterAvailable`**: `adapter_key` is not null **and** is registered in the default adapter registry (`lib/extraction/adapters/default-registry.ts`).
2. **Formatters**, pure functions usable in server and client components (US-019 reuses them in a client chart):
   - `formatNumber(canonical: string, locale)`, e.g. `lib/format/number.ts` (DEC-007). It works on the canonical string: keep every digit as stored, drop nothing, replace `.` by `,` for `ro`, and never insert a grouping character. See the Notes for the `Intl.NumberFormat` trap;
   - `formatReportDate(isoDate: string, locale)`, e.g. `lib/format/date.ts`, with the format of decision 5. It must not shift the day. Do not parse the string as a local `Date`;
   - set `timeZone: "Europe/Bucharest"` in `i18n/request.ts` (decision 4; Sprint 1 audit N2).
3. **Page**: `app/page.tsx` becomes an async Server Component that loads the view model and renders a presentational table component (e.g. `components/HomeTable.tsx`) that receives the view model as props, so it can be render-tested without a database:
   - the symbol is an `<a href={latestPdfUrl} target="_blank" rel="noopener noreferrer">` when a link exists, and plain text otherwise;
   - each row shows its `valueDate` (formatted), or nothing when the ETF has no `ok` report;
   - an ETF whose adapter is not available shows a translated "extraction unavailable" marker (section 3);
   - no active ETFs → a translated empty-state message;
   - database error → a translated generic error message. Never render the exception text, which can contain connection details (AGENTS.md secrets rule).
4. **Messages**: add the new `Home.*` keys to both `messages/ro.json` and `messages/en.json`. Remove the placeholder `Home.intro`, and update `app/page.test.tsx`.
5. **Tests**:
   - PGlite tests for the read model: rows, columns, newest-`ok` rule, newest-link rule, the parse_error exclusion, and the configuration change of AC2;
   - pure unit tests for both formatters;
   - `renderToStaticMarkup` tests of the table component in `ro` and `en`, as `app/page.test.tsx` does today;
   - one test for the page's database-error path, with the loader injected or mocked.

## Acceptance criteria

- **AC1** — Rows. The table has exactly one row per ETF with `is_active = true`, ordered by symbol. An inactive ETF has no row. An active ETF with no report and an active ETF with `adapter_key` NULL each still get a row. (FR7 "all currently monitored ETFs"; data model `etfs.is_active` "soft removal from monitoring"; section 3 "the ETF is still shown in the list")
- **AC2** — Columns come from configuration, not code.
  - The columns are the tracked fields under the union and order rule of decision 3.
  - A PGlite test inserts a `tracked_fields` row and the new column appears at its `display_order` position. It deletes the row and the column disappears. No code changes between the two reads.
  - A cell for a field the ETF does not track is empty and is distinguishable in the view model (`tracked: false`) from a tracked field with no value.
  - Each header is the `field_catalog` label for the current locale (`label_ro` / `label_en`).

  (FR7 "Dynamic columns … configurable"; FR2; FR10; data model `tracked_fields.display_order` "column order on the home table"; US-004 out of scope: database content carries its own `label_ro`/`label_en`)
- **AC3** — Values. Each tracked cell shows that field's `numeric_value` from the ETF's newest `ok` report, and the row shows that report's date.
  - When the newest `ok` report has no value for a tracked field, the cell is empty. It is never filled from an older report.
  - An ETF with no `ok` report has empty value cells and no date.
  - A newer `parse_error` row, including one with stored values, changes no value and no date (decision 2).

  (FR7 "today's value" with decision 1; FR4.1 "no value"; AGENTS.md "Never guess a value"; Sprint 3 decision 5 forward note)
- **AC4** — PDF link. The symbol links to the `source_url` of the ETF's newest report row that has one, whatever its status, and opens in a new tab. An ETF with no such row shows its symbol as plain text. No URL is ever built from the symbol, the `bvb_url` or a date. (FR7 "clickable, linking directly to the most recent PDF report"; data model `reports.source_url`; AGENTS.md "Never guess a value")
- **AC5** — Extraction unavailable. An active ETF whose `adapter_key` is NULL, or is not in the adapter registry, shows a translated "extraction unavailable" marker in its row and is still listed. Its values follow AC3 like any other row. A test covers both the NULL key and an unregistered key. (Section 3 "automatic extraction is marked 'unavailable'"; FR13; data model `etfs.adapter_key` NULL = no adapter matched)
- **AC6** — Numbers follow DEC-007. `formatNumber` unit tests:
  - `415591664.27` → `ro` `415591664,27`, `en` `415591664.27`;
  - `37470000` → `37470000` in both;
  - `54.1373` → `ro` `54,1373` (no digit dropped or rounded);
  - `8640000.00` → `ro` `8640000,00` (trailing zeros kept as stored);
  - `-0.006` → `ro` `-0,006`;
  - no output ever contains a grouping character (`,` in `en`, `.` in `ro`, space, NBSP, apostrophe).

  Every value in the table goes through `formatNumber`. (DEC-007; data model notes on `numeric_value`/`raw_value` and variable decimal places)
- **AC7** — Report dates. `formatReportDate` gives the format of decision 5 (`2026-09-22` → `ro` `22.09.2026`, `en` `2026-09-22`). It returns the same calendar day for year and month boundaries (`2026-01-01`, `2026-12-31`, `2028-02-29`), and it does not depend on the process time zone. `i18n/request.ts` sets `timeZone: "Europe/Bucharest"`. (FR8.1; Sprint 1 audit N2; data model `reports.report_date` "the date the report is **for**")
- **AC8** — Bilingual. Every user-facing string of the page goes through next-intl, with keys in both catalogues. The key-parity test (`i18n/messages.test.ts`) still passes. Render tests in `ro` and `en` show the locale's headers, marker, empty-state text and decimal mark, and neither render contains the other locale's differing text. (FR8.1; AGENTS.md "Every UI string goes through next-intl"; DEC-007)
- **AC9** — Failure and empty states. With no active ETF, the page shows a translated empty-state message. When the database read throws, the page shows a translated error message, does not throw, and contains neither the exception message nor any environment value. (FR7; AGENTS.md "Secrets only in environment variables … Never … print"; EPIC-04)
- **AC10** — Offline and build-safe. The read-model tests run on PGlite with `drizzle/0000_init.sql`, executing the same statements the page runs. No test connects to Neon. `pnpm build` passes with `DATABASE_URL` unset, because the page reads the database per request and never at build time. (AGENTS.md "Tests never call live Neon"; ADR-001; DEC-010)
- **AC11** — `pnpm typecheck`, `pnpm lint`, `pnpm test` and `pnpm build` pass. (AGENTS.md Commands)

## Decisions needed

1. **PRODUCT — what is "today's value"?** (non-blocking) A report for day D is filed on the morning of D+1 (`test/fixtures/bvb/README.md` §4, "the row title's own date … is one day behind the filing timestamp's date"), and the cron runs after that (US-013). So a report whose `report_date` equals the viewing day never exists.
   - A: the newest `ok` report, with its date shown in the row. **This story implements it.**
   - B: only a report whose `report_date` is today. The table would always be empty.
   - C: the newest `ok` report without showing its date. Staleness (a missing day, FR4.1) would be invisible.
   - Recommendation: **A**.
2. **PRODUCT — values under `parse_error` rows** (sprint-03.md forward note; applies to US-016..US-019). (non-blocking)
   - A: show only `ok` rows everywhere in Sprint 4. **This story implements it.**
   - B: also show the values found in a `parse_error` row, next to a visible flag.
   - Recommendation: **A**. It is the simplest reading of FR4.1 ("no value") and it never mixes a flagged report into "today". FR13 makes parse errors visible in the admin area (US-024). If the PO picks B, the change is in the read model's `ok` filter and one marker.
3. **TECHNICAL — columns when ETFs track different fields.** `display_order` is per ETF, but the table has one header row.
   - A: the union of the active ETFs' tracked `field_key`s, ordered by the lowest `display_order` any ETF gives the field, then `field_key`. A cell for a field that ETF does not track is empty. Header label from `field_catalog` for the locale (the first `adapter_key` alphabetically if several adapters define the key), falling back to `field_key` if no catalogue entry exists.
   - B: only fields every active ETF tracks (intersection). A field tracked by one ETF would be invisible.
   - Recommendation: **A**. For the in-loop `tech-lead` to settle.
   - **Decided: A** (tech-lead sprint review, 2026-09-25). The union is the only rule under which every ETF shows every parameter its user chose (FR7, FR2). The intersection would hide configured fields. The alphabetical label tie-break is deterministic and only matters once a second adapter defines the same `field_key`.
4. **TECHNICAL — time zone.** `timeZone: "Europe/Bucharest"` in `i18n/request.ts`, as Sprint 1 audit N2 already says. Report dates are date-only and are formatted without conversion. For the in-loop `tech-lead` to confirm.
   - **Decided** as written (tech-lead sprint review, 2026-09-25).
5. **PRODUCT — report-date format.** (non-blocking) DEC-007 covers numbers only.
   - A: `ro` `22.09.2026` (BVB's own day-first format, README §4), `en` `2026-09-22` (ISO, no US/UK ambiguity). **This story implements it**, in one function.
   - B: `en` `22/09/2026` (en-GB).
   - C: `en` `09/22/2026` (en-US).
   - Recommendation: **A**.

## Notes for verification

- **`Intl.NumberFormat` trap.** DEC-007 suggests `useGrouping: false`, but `Intl.NumberFormat`'s default `maximumFractionDigits` is 3. It would round VUAN `54.1373` to `54.137`, and it would drop `8640000.00`'s trailing zeros. AC6's cases catch both. A string-based formatter over the canonical value avoids the problem entirely.
- **Existing scaffold `lib/format.ts`** (US-002) already exports a `formatNumber(value: number)` that does `toFixed(2)`. That breaks DEC-007: it rounds and it takes a float. It is a placeholder, and its comment says so. This story replaces it: at the end there is exactly one `formatNumber`, the DEC-007 one, and no module that shadows it (`lib/format.ts` next to `lib/format/number.ts` would make `./format` resolve to the old file). The scaffold's one test tested only the placeholder, not a requirement, so replacing it with the AC6 tests is not weakening a test. The plan lists it. (Tech-lead sprint review, 2026-09-25.)
- `numeric_value` comes back from both Neon HTTP and PGlite as a string. Keep it a string through the view model. Never `parseFloat` a value for display.
- The link rule (any status) and the value rule (`ok` only) deliberately differ: the symbol always opens the newest PDF, and the row's date says which report the values are from. The reviewer checks both in the PGlite tests (a newer `parse_error` row with a `source_url` changes the link but not the values).
- `adapterAvailable` reads the registry. That is a pure import from `lib/extraction/adapters/`, and needs no network.
- The reviewer checks that `app/page.tsx` is not prerendered with database access: `pnpm build` with `DATABASE_URL` unset must pass (AC10). The layout already reads the locale cookie, which makes rendering dynamic (Sprint 1 audit N3). If the plan relies on that, it says so, and a test or build log shows it.
- Sharing `BatchRunner`/`rowsOf` is fine. If they move from `lib/ingestion/store.ts` to a shared module, Sprint 3's tests must stay green unchanged.
- **Manual QA (live, user):** sprint-04.md steps 1, 2, 4 and 5.
