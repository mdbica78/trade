# US-022 — Admin: AI provider and API key settings
> Detailed by agent (story-planner), 2026-09-26 — PO to confirm at demo.

**Sprint:** 5 · **Epic:** EPIC-05 · **Depends on:** US-020
**Suggested model / thinking:** mid model, medium thinking. Complex (first piece of the AI provider system, secrets boundary, 8 ACs), so it is planned by `story-planner`.

## Context

FR11: "AI module configuration: choice of AI provider (from the list of supported free ones) + entering an API key where required." FR6: the user chooses "which AI model powers the conversational interface, from a list of integrable free options (the architecture must be 'pluggable' — a single AI-provider adapter, easy to swap)". FR6 names Google Gemini, Groq, OpenRouter and Mistral, and says "the exact set of supported providers is to be validated at implementation time". FR5: the AI is used only for configuration.

What exists and what binds this story:
- `settings` (data model): single row (`id = 1`), with `ai_provider` and `ai_model` (both NULL today), `cron_hour_utc` (US-023) and `default_locale`. The seed creates the row, and after US-020 a seed re-run no longer overwrites it.
- **Secrets rule** (AGENTS.md "Secrets", DEC-015): "Secrets live only in environment variables, server-side. Never commit, log or print one." A provider API key is a secret. FR11's "entering an API key" therefore needs a decision (sprint decision 9). This story ships the default that keeps the rule: keys are environment variables, and the page only shows whether each is set.
- The provider **adapters** are Sprint 6 (US-025 interface, US-026 two concrete providers). This story needs only the list to choose from (sprint decision 10). Carry-forward: "API keys are live steps for the user, never handled by agents."
- US-020 provides the admin shell and the `lib/config/` pattern.

## Task

1. **Provider catalogue**, `lib/ai/provider-catalog.ts` (sprint decision 10). Static data only, with no network code and no SDK: for each provider an `id`, a display name, `requiresApiKey`, and `apiKeyEnvVar` (e.g. `GEMINI_API_KEY`). It holds the four providers FR6 names. Sprint 6 attaches adapters to these ids and trims the list.
2. **Configuration layer**, e.g. `lib/config/ai-settings.ts` (same rules as `lib/config/etfs.ts`):
   - `getAiSettings()` returns `{ provider, model }` from `settings`;
   - `setAiSettings({ provider, model })` accepts a catalogue id or none, and a model string (trimmed; blank → NULL; a length limit the plan names). It writes **only** `ai_provider` and `ai_model`, with an upsert on `id = 1` that leaves every other column unchanged and creates the row if it is missing. Clearing the provider also clears the model.
3. **Key status**, a server-only function, e.g. `lib/ai/key-status.ts`: for each provider, `isSet = typeof process.env[apiKeyEnvVar] === "string" && value.trim() !== ""`. It returns booleans only. The value never leaves the function.
4. **Page** `app/admin/ai/page.tsx` plus an admin nav entry: a provider select (catalogue + "none"), an optional model field, and save. A table lists each provider with "key required", its variable name, and "set" / "not set". A translated note says keys are set as environment variables in the Vercel project (then redeploy), never in this form. Another note says the configuration chat is not available yet (Sprint 6). The Server Action is as in US-020 (no SQL, no exception text).
5. **`.env.example` and README:** add the four variable names with empty values and a one-line comment each. README "Environment variables" lists them as optional until Sprint 6.
6. **Messages:** new `Admin.*` keys in both catalogues.
7. **Tests:** PGlite tests for `lib/config/ai-settings.ts`. Unit tests for the key status with `vi.stubEnv`. Render tests in `ro` and `en`, including one where every key variable holds a sentinel value that must not appear in the HTML.

## Acceptance criteria (DRAFTED BY AGENT — PO to confirm)

- **AC1** — Choice from the supported list. The page offers exactly the providers in `lib/ai/provider-catalog.ts`, plus "none", and preselects the stored `ai_provider`. The stored `ai_model` is shown in the model field. (FR11 "choice of AI provider (from the list of supported free ones)"; FR6; data model `settings.ai_provider`, `settings.ai_model`; decision 10)
- **AC2** — Save writes only its columns. Saving a catalogue provider and a model sets `ai_provider` and `ai_model` and nothing else. A PGlite test sets `cron_hour_utc` and `default_locale` first and finds them unchanged afterwards. With no `settings` row, saving creates row `id = 1`. Clearing the provider sets both columns to NULL. (FR11; data model `settings` "single-row app configuration"; US-020 decision 1 "never overwrite admin changes")
- **AC3** — Validation. A provider id not in the catalogue, or a model over the length limit, returns a validation error, writes nothing, and the page shows a translated message. (FR11 "from the list of supported free ones")
- **AC4** — Keys stay in the environment. For each provider the page shows whether its key variable is set, and its variable name. A render test stubs every key variable with a distinctive sentinel value: the sentinel appears nowhere in the HTML, and the "set" marker does. An unset or blank variable shows "not set". The form has no key input, and no key is written to the database. (FR11 "where required"; AGENTS.md "Secrets live only in environment variables, server-side. Never … print one"; DEC-015 point 1; decision 9)
- **AC5** — No AI call, no network. Loading or saving the page makes no network request and imports no AI SDK. `lib/ai/provider-catalog.ts` is static data. A boundary test checks the imports. (FR5 "used exclusively for configuration"; AGENTS.md "Tests never call … AI providers"; decision 10)
- **AC6** — Bilingual. Every string (labels, provider table headers, set/not-set markers, both notes, errors) goes through next-intl with keys in both catalogues, and the key-parity test passes. Render tests in `ro` and `en` show the locale's text and not the other's. Provider display names are proper nouns and are the same in both. (FR8.1)
- **AC7** — Failure states. A database read error gives a translated message on the page. A failing save returns a translated error. Neither contains exception text or an environment value. (AGENTS.md secrets rule; US-020 AC9 pattern)
- **AC8** — Documentation and gates. `.env.example` lists each catalogue provider's key variable with an empty value. No test connects to Neon or an AI provider. `pnpm typecheck`, `pnpm lint`, `pnpm test` and `pnpm build` (with `DATABASE_URL` unset) pass. (AGENTS.md Commands, Secrets; ADR-001)

## Out of scope

- The chat surface (US-028).

## Notes for verification

- `lib/ai/key-status.ts` must be server-only (it reads `process.env`). The reviewer checks that no client component imports it and that its return type holds no string derived from the value (e.g. no "last four characters").
- Stubbing the variables in the render test with values like `SENTINEL-GEMINI-9f3c` proves AC4 against the real page code. Use `vi.stubEnv` and `vi.unstubAllEnvs`. Never read or print the real environment (DEC-015).
- The FR11 wording "entering an API key" is **not** met by this default. The QA checklist lists it as a PO decision, not as a failed criterion.
