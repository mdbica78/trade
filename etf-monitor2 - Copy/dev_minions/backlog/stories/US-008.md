# US-008 — PDF download and text extraction service
> Detailed by agent (story-planner), 2026-09-23 — PO to confirm at demo.

**Sprint:** 2 · **Epic:** EPIC-02 · **Depends on:** US-002
**Suggested model / thinking:** cheap model, low thinking. Plan in-session (6 ACs, no framework change).

## Context

FR3: the system downloads the most recent depositary report and extracts the selected parameters. Extraction is a classic deterministic parser, never AI (FR5). It works on the PDF's text. The US-001 spike proved that `unpdf` extracts every target field from all three BRD fixtures, with no OCR (`spikes/pdf-extraction/FINDINGS.md`), and ADR-001 fixes `unpdf` as the PDF library.

This story adds two small functions, each with one job:
- download bytes from a URL and make sure they are a PDF;
- turn PDF bytes into text.

Adapters (US-009/US-010) receive only the text, so they never touch the network or a PDF library.

## Task

1. `pnpm add unpdf` (ADR-001). Do not add `pdfjs-dist` or `pdf-parse` to the app: loading `unpdf` and `pdfjs-dist` in the same process breaks with a version clash (FINDINGS, "pdfjs-dist … trap").
2. `downloadReportPdf(url, deps?: { fetchImpl?, timeoutMs? })`, e.g. in `lib/extraction/pdf.ts`, returns one of:
   - `{ ok: true, bytes: Uint8Array, fetchedAt: Date }`
   - `{ ok: false, kind: "http_error" | "network" | "timeout" | "not_pdf", message, httpStatus? }`

   Check the `%PDF-` signature of the body rather than trusting `Content-Type`. An HTML error page served with status 200 must come back as `not_pdf`. The call makes exactly one attempt (FR4.1) and never throws. The plan picks and documents the default timeout.
3. `extractPdfText(bytes)` returns `{ ok: true, text }` or `{ ok: false, kind: "unreadable", message }`. It uses `unpdf`'s `getDocumentProxy` + `extractText({ mergePages: true })`, the call the spike validated. It returns one string and never throws.
4. Unit tests: the three committed PDFs in `test/fixtures/` for extraction, and a mocked `fetch` for download.

## Acceptance criteria

- **AC1** — `unpdf` is a runtime dependency in the root `package.json`. Neither `pdfjs-dist` nor `pdf-parse` is. (ADR-001; FINDINGS "Recommendation")
- **AC2** — `extractPdfText` on each of `test/fixtures/BTBETRETF-2026-09-21.pdf`, `TVBETETF-2026-09-21.pdf` and `PTENGETF-2026-09-21.pdf` returns `ok: true`, and the text contains each of these labels: `ACTIV NET (in valuta fond - RON)`, `NUMAR U.F. in circulatie, din care detinute de:`, `VALOARE UNITARA A ACTIVULUI NET (VUAN) (RON)`, `Numar investitori, din care:`, `Raport depozitar la data de`. (FR3; US-001 step 4 field list)
- **AC3** — `extractPdfText` on bytes that are not a readable PDF (a truncated fixture, or random bytes) returns `ok: false`, `kind: "unreadable"`, and does not throw. (FR13 failures visible; AGENTS.md "Never guess a value")
- **AC4** — With a mocked `fetch`, `downloadReportPdf` behaves as follows, and in every case calls `fetch` exactly once and never throws:
  - a 200 response with fixture PDF bytes gives `ok: true` with those exact bytes and a `fetchedAt`;
  - a 404 or 500 gives `http_error` with the status;
  - a 200 response whose body is HTML gives `not_pdf`;
  - a rejected promise gives `network`;
  - a response slower than `timeoutMs` gives `timeout`.

  (FR3; FR4.1 no retries; FR13; data model `reports.fetched_at`)
- **AC5** — Tests read fixtures from disk and never perform a real network request. (AGENTS.md; `roles/test-runner.md`)
- **AC6** — `pnpm typecheck`, `pnpm lint`, `pnpm test` and `pnpm build` pass. (AGENTS.md Commands)

## Out of scope

- Finding the URL (US-007). Parsing fields out of the text (US-010).
- Storing the PDF or the text anywhere. Only `source_url` and `fetched_at` are persisted, in Sprint 3.
- OCR (FINDINGS: not needed).
- Wiring `unpdf` into a Next.js route. The first route to import it is the Sprint 3 cron endpoint.

## Notes for verification

- `unpdf` prints `Warning: TT: undefined function: 32` to stderr for these fixtures (FINDINGS). It is harmless. Silencing it is allowed, but not required.
- The spike ran `unpdf` 0.11.0. The version added here may be newer, and AC2 is what re-proves the API on the committed fixtures.
- `unpdf`'s flattened output (single spaces, no line breaks) is the format US-010's rules are written against. Do not post-process the text in ways that change token order.
