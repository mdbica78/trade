# US-002 — Project scaffold

**Sprint:** 1 · **Epic:** EPIC-01 · **Depends on:** ADR-001 confirmed
**Suggested model / thinking:** cheap model, low thinking

## Context

Greenfield project. The project folder (`etf-monitor2/`) currently contains only documentation (`dev_minions/`). This story creates the application skeleton it will grow into. Stack is fixed by ADR-001 — do not substitute alternatives.

**Important — repository structure:** this project lives in the `etf-monitor2/` subfolder of the `trade` git repository, alongside unrelated sibling projects (including an older, abandoned, unrelated folder named `etf-monitor` — do not read, reference, or touch it). Everything in this story is scoped to `etf-monitor2/`. "Repository root" below means the `etf-monitor2/` folder itself, not the top of the `trade` git repo.

## Task

Initialise a Next.js application inside the `etf-monitor2/` project root (do **not** create it at the top of the `trade` git repository, and do not touch the sibling `etf-monitor/` folder), using the App Router and TypeScript, with Tailwind CSS, Vitest, and pnpm.

Create this structure:

```
app/                  — routes (App Router)
lib/                  — shared code
  db/                 — database client and schema (filled by US-003)
  extraction/         — adapters and PDF handling (filled in Sprint 2)
components/           — React components
messages/             — i18n catalogues (filled by US-004)
test/
  fixtures/           — sample PDFs (from US-001)
```

Configuration requirements:
- TypeScript `strict: true`.
- Vitest configured to run `*.test.ts` / `*.test.tsx`, with a `pnpm test` script.
- ESLint with the Next.js config, and a `pnpm lint` script.
- `.gitignore` covering `node_modules`, `.next`, `.env*` (except `.env.example`), and build output.
- `.env.example` listing every environment variable the project will need, starting with `DATABASE_URL` and `CRON_SECRET`, each with a one-line comment.
- `README.md` at the `etf-monitor2/` project root: what the project is, how to install, run, test, and where the process documentation lives (`dev_minions/`). Replace the current placeholder content.

Add one trivial passing test (for example, a pure helper that formats a number for display) so `pnpm test` is meaningful from the start rather than running an empty suite.

## Acceptance criteria

- **AC1** — `pnpm install && pnpm dev` starts the app and the default page renders without errors.
- **AC2** — `pnpm test` runs Vitest and reports at least one passing test.
- **AC3** — `pnpm lint` completes with no errors.
- **AC4** — `pnpm build` completes successfully.
- **AC5** — All folders listed above exist (empty ones with a `.gitkeep`).
- **AC6** — `.env.example` exists and documents `DATABASE_URL` and `CRON_SECRET`; no real secret values are committed anywhere.
- **AC7** — Root `README.md` describes install/run/test and points to `dev_minions/`.

## Out of scope

- No database connection (US-003), no i18n (US-004), no deployment (US-006).
- No UI design work beyond whatever the scaffold generates — do not build layouts, navigation, or styling systems yet.
- Do not add dependencies beyond those named in ADR-001 and this story.
