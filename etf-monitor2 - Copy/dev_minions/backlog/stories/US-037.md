# US-037 — Ingest every report in the newest filing (Mon = Fri+Sat+Sun) and store every extracted field
> Detailed by agent (story-planner), 2026-09-28 — PO to confirm at demo.

**Sprint:** 9 · **Epic:** EPIC-08 · **Depends on:** US-035 (build order only), US-012, US-014, US-029, US-030
**Suggested model / thinking:** strong model, high thinking. Complex: a change to report discovery, the ingestion outcome path and the cron run budget (DEC-018 §5 amended), 10 ACs. So it is planned by `story-planner`.

## Context

- **FR3.1** (decided 2026-09-28): "The BVB news list files one entry per day, and a Monday entry holds Fri+Sat+Sun reports ('VAN la data 25/26/27.09.2026'). The system stores **every** report in the newest filing row, each under its own report date, and stores every field the adapter extracts." This replaces P2 ("newest only") and adopts the P1 recommendation ("every field").
- **FR7.3:** "Storage is independent of display: every extracted field is stored (FR3.1) and the display choice only filters."
- **Sprint 9 review §3 T-1** is the binding design (discovery, per-link skip, every field, outcome, budget), and **DEC-018 §5 as amended** holds the budget.
- **What exists:**
  - `lib/extraction/discovery.ts`: `parseReportList` already exposes `rowIndex` and `linkIndexInRow` per entry. `findLatestReportLink` picks the newest row by `publishedAt`, and inside that row **the later link wins** (fixtures README §2: a row's links are listed in ascending date order, e.g. `…18-09-2026.pdf`, `…19-09-2026.pdf`, `…20-09-2026.pdf`). `discoverLatestReport` returns one `found` link.
  - `lib/ingestion/ingest-etf.ts`: `ingestEtf` = one discovery + `ingestReport` for one link. Its comment says `ingestReport` is "kept separate so a future change to discovery (e.g. every link in a filing row) only changes `ingestEtf`". `persist` skips an existing `ok` row (`already_ingested`), and `store.ts` guards every write `status <> 'ok'` (DEC-010).
  - `lib/ingestion/select-values.ts` keeps only tracked keys. Its comment names it as "the one function PRODUCT decision 1 changes".
  - `lib/ingestion/run-daily.ts`: `MAX_REQUESTS_PER_ETF = 2`, `CRON_FETCH_TIMEOUT_MS = 7000`, `PARSE_ALLOWANCE_MS = 5000`, `FINISH_RESERVE_MS = 5000`, `CRON_MAX_DURATION_S = 60`, `canStartEtf` (worst case = `MAX_REQUESTS_PER_ETF` requests), `not_attempted`.
  - The budget test (`app/api/cron/daily/route.test.ts`, the RT-7b successor from US-030) and `lib/ingestion/request-bound.test.ts` (US-029) are expressed over `MAX_REQUESTS_PER_ETF`.
  - `reports` is unique on `(etf_id, report_date)`. `report_values.field_key` has no foreign key, so any key an adapter emits is storable.
  - The no-adapter branch (US-030) and add-time detection (US-020) use discovery's single newest link.
- **Fixtures:** each BRD page fixture's **third** row is a three-link catch-up filing (README §2). The committed PDFs are `*-2026-09-21.pdf` and `*-2026-09-22.pdf` per BRD ETF, plus `ICBETNETF-2026-09-24.pdf`. The 18/19/20 PDFs are not committed.

## Task

1. **Discovery (T-1, sprint D-1).**
   - Add `findLatestFilingLinks(html, pageUrl)`. It returns every depositary-report link of the newest row (the row `findLatestReportLink` picks today), newest first (D-1), capped at `MAX_REPORTS_PER_FILING = 4`. The cap keeps the newest links, and the result says whether it truncated.
   - `findLatestReportLink` becomes a wrapper returning the first element, i.e. exactly today's result.
   - The `found` discovery result carries the full list, while keeping `pdfUrl`/`title`/`publishedAt` as the newest link. So detection (`lib/config/detect-adapter.ts`) and the no-adapter branch keep their single-link behaviour unchanged.
2. **Per-link ingestion (T-1).** `ingestEtf`, adapter branch:
   - Run one query per ETF: the `source_url`s among the kept links that already have an `ok` report for this ETF (`source_url = any(...)`), added to `ReportStore` or a sibling read.
   - Each such link is skipped with no request ("already stored").
   - For every other link, in order: check `canStartDownload` (Task 4), then `ingestReport` (download → extract → `report_date` from the PDF's own text → DEC-010 write, one batch per report, `ok` last, never downgraded).
   - A link whose PDF resolves to a date already stored `ok` in the same filing is a no-op (`persist` → already stored).
3. **Every field (T-1, P1 answered).**
   - `selectValuesToPersist` returns every value the adapter extracted, and its comment is updated.
   - The `ok`/`parse_error` status rule stays as today (sprint D-3): a tracked key missing from the adapter's values still makes the report `parse_error`, now with every found value stored.
   - Tracked fields remain the selection for the detail page's history and charts, and for the home table's default columns.
4. **Budget (T-1; DEC-018 §5 amended).**
   - `MAX_REPORTS_PER_FILING = 4` and `MAX_REQUESTS_PER_ETF = 1 + MAX_REPORTS_PER_FILING`, as named constants next to the others.
   - `canStartEtf` keeps its meaning but checks the minimum (discovery + one PDF = 2 requests, via a named constant).
   - New `canStartDownload(now, startedAt)`: `now + CRON_FETCH_TIMEOUT_MS + PARSE_ALLOWANCE_MS <= runDeadlineMs(startedAt)`. It is checked before every PDF after the first. When it fails, that link and all remaining ones are `not_attempted` (no request).
   - `ingestEtf` gets the run's `startedAt` (or a download guard function) through `IngestDeps`, wired from `runDailyIngestion`'s budget. The clock stays injected.
   - `CRON_FETCH_TIMEOUT_MS`, `PARSE_ALLOWANCE_MS`, `FINISH_RESERVE_MS` and `CRON_MAX_DURATION_S` do not change.
5. **ETF outcome (T-1, sprint D-2).**
   - One outcome per ETF from the closed codes (unchanged list). Priority: failure code > `not_attempted` > `ok` > `already_ingested` (D-2).
   - The detail line states "stored N, already stored M, failed K, not attempted J", plus `truncated` when the cap applied.
   - It never contains a URL fragment beyond what today's details already carry, and no secret (the existing redaction still applies in `job_runs.log`).
6. **Docs.** `architecture/data-model.md` "Write rules": several reports per filing, one batch each; every extracted field is stored; tracked fields select what is displayed, not what is stored.
7. **Tests.**
   - Unit tests with stubbed `discover`/`download`/`extractText`, including a fake clock for the guard.
   - PGlite tests over a page built from the committed fixtures, with the two real PDFs per ETF (21 and 22) placed in one synthetic newest row.
   - The plan lists every existing test whose expectation changes (value counts, `valuesWritten`, the budget test, request-bound counts) and the AC of this story that replaces it.

## Acceptance criteria (DRAFTED BY AGENT — PO to confirm)

- **AC1** — Every report in the filing (review §2 US-037 (1)).
  - Given a newest filing row with 3 PDF links whose PDFs carry 3 different report dates, one run stores 3 `reports` rows, each under the date read from its own PDF text, with its own `source_url` and values.
  - Covered by a unit test with 3 stubbed PDFs, and by a PGlite test over the committed fixtures (2 real PDFs in one synthetic row, the shipped statements).
  - No date comes from the row title, the filing stamp or the clock.
  (FR3.1; DEC-010; data-model "Write rules" `report_date` rule; AGENTS.md "The report date comes from the PDF")
- **AC2** — Every field (review §2 US-037 (2)).
  - For an ETF tracking 2 fields, an `ok` report stores one `report_values` row for **every** field the adapter returned (PGlite, BRD fixture: every key in the adapter's `values`), not only the 2 tracked ones.
  - A tracked key the adapter did not return still gives `parse_error`, with every found value stored (sprint D-3).
  (FR3.1 "stores every field the adapter extracts"; FR7.3 "Storage is independent of display"; P1 answered; US-014 AC5)
- **AC3** — Idempotent by URL, and completes on re-run (review §2 US-037 (3)).
  - A second run over the same row makes **only** the discovery request (counting `fetch`) and writes nothing to `reports` or `report_values` (row counts and `fetched_at` unchanged). The run's own `job_runs` row is still written as usual, and the ETF's outcome is `already_ingested` (sprint D-2).
  - A run where link 2 of 3 fails to download stores links 1 and 3. The next run downloads only link 2 and stores it.
  - The "already stored" check is one query per ETF, not one per link.
  (FR3.1; review T-1 (a); FR4.1 "no automatic retries" — the re-run is the next scheduled or manual run, never a retry loop)
- **AC4** — Never downgraded, duplicate date harmless (review §2 US-037 (4)).
  - An existing `ok` report is never overwritten or downgraded, whatever a later link yields (`parse_error`, a different URL for the same date).
  - Two links in one filing that resolve to the same `report_date` store one report. The second is a no-op, not an error.
  - The PGlite tests read back status, `source_url` and values.
  (DEC-010; data-model "Write rules"; review T-1)
- **AC5** — Deadline guard per download (review §2 US-037 (5)).
  - With a fake clock that passes the `canStartDownload` limit after the first PDF, the remaining links are `not_attempted` and make no request.
  - Links already finished keep their real result (stored, already stored, failed) in the counts.
  - The ETF outcome follows the priority of Task 5, and its detail has the four counts.
  - `summarizeRun` counts the ETF as an error (existing rule for `not_attempted`), and the run ends with a final status and one log line per ETF.
  (DEC-018 §5 amended; review T-1 budget; FR13; US-030 AC7)
- **AC6** — Display unchanged by storage (review §2 US-037 (6)). After a run that stores untracked fields:
  - the home loader, with no display settings, shows exactly the tracked-union columns as before;
  - the detail page's history and chart loader shows only tracked fields.
  PGlite, shipped loaders.
  (FR7.3 "the display choice only filters"; P-1)
- **AC7** — Budget constants.
  - `MAX_REPORTS_PER_FILING === 4` and `MAX_REQUESTS_PER_ETF === 1 + MAX_REPORTS_PER_FILING`.
  - The budget test is rewritten over the constants as a deliberate part of the DEC-018 amendment. It asserts:
    - `MAX_REQUESTS_PER_ETF × CRON_FETCH_TIMEOUT_MS + PARSE_ALLOWANCE_MS + FINISH_RESERVE_MS ≤ CRON_MAX_DURATION_S × 1000`;
    - a computed counter-case (not hard-coded) fails when a constant outgrows the budget;
    - `route.maxDuration === CRON_MAX_DURATION_S`.
  - `canStartEtf` checks the 2-request minimum.
  - `STALE_RUN_THRESHOLD_MS` and the other timeout constants are unchanged.
  (DEC-018 §5 amended; review T-1)
- **AC8** — Request bound and truncation.
  - A counting-`fetch` test over a row with 6 links makes at most `MAX_REQUESTS_PER_ETF` requests (1 discovery + 4 PDFs), keeps the 4 newest links (sprint D-1), and says `truncated` in the detail.
  - `findLatestReportLink` returns exactly what it returns today on every committed page fixture (existing discovery tests unchanged).
  - `findLatestFilingLinks` on each BRD fixture's three-link row returns the three links, newest first.
  - Detection (US-020) and the no-adapter branch (US-030) still make exactly one discovery request and use the single newest link (existing tests unchanged).
  (DEC-018 §1, §5; review T-1; US-007; fixtures README §2)
- **AC9** — Docs. `architecture/data-model.md` "Write rules" states the per-filing rule (one DEC-010 batch per report, URL-identity skip), the "every extracted field is stored" rule, and that tracked fields select display, not storage. (FR3.1; data-model "Write rules")
- **AC10** — Offline and gates.
  - No test calls bvb.ro or Neon: `fetch` is mocked over the committed fixtures, and SQL runs on PGlite with every migration.
  - No schema change, no new dependency.
  - `pnpm typecheck`, `pnpm lint`, `pnpm test` and `pnpm build` pass with `DATABASE_URL`, `CRON_SECRET` and `VERCEL_ENV` unset.
  (AGENTS.md "Tests never call live Neon, Vercel, bvb.ro"; Commands)

## Out of scope

- Backfilling untracked fields into reports stored before this story (P-3).
- Fetching a deadline-skipped link on the next daily run. The next run's newest row is a different one, so the link is fetched by a same-day manual run from `/admin/cron`, which downloads only what is missing (review T-1 "known limit").
- Older filing rows (catch-up beyond the newest row), retries, alerts (FR4.1, FR4.2).
- Any change to what the home table or charts display (US-047, US-036, US-038).
- A second access mechanism or adapter change (DEC-018 §1–§3 unchanged).
