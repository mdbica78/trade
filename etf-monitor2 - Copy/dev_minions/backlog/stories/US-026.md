## Task

1. **Gemini adapter**, e.g. `lib/ai/providers/gemini.ts` (sprint decision 5):
   - `POST https://generativelanguage.googleapis.com/v1beta/models/<model>:generateContent`, with `<model>` passed through `encodeURIComponent`.
   - The key goes only in the `x-goog-api-key` header, never in the query string.
   - The body carries `systemInstruction` from `request.system`, one user `contents` part from `request.user`, and `generationConfig.maxOutputTokens`. When `request.json` is set, it also carries `generationConfig.responseMimeType = "application/json"`.
   - The response text is the first candidate's text parts, joined.
2. **Groq adapter**, e.g. `lib/ai/providers/groq.ts`:
   - `POST https://api.groq.com/openai/v1/chat/completions`, with `Authorization: Bearer <key>`.
   - The body carries `model`, a `messages` list (`system`, `user`) and `max_tokens`. When `request.json` is set, it also carries `response_format: { type: "json_object" }`.
   - The response text is `choices[0].message.content`.
   - Write the OpenAI-compatible part so that another compatible provider would be one more small entry (sprint-06 Sprint 7 note), without building more than Groq now.
3. **Error mapping** (the same for both adapters, except the provider-specific rows the tech-lead added on 2026-09-26, see "Tech-lead review"):
   - 401/403 → `auth_failed`;
   - Gemini only: 400 whose JSON error body has a `details[].reason` of `API_KEY_INVALID` → `auth_failed` (Gemini answers a wrong key with 400, not 401);
   - 404 → `model_not_found`;
   - 429 → `rate_limited`;
   - Groq only: 400 whose JSON error body has `error.code` `json_validate_failed` → `bad_response`;
   - any other non-2xx → `provider_error`;
   - `fetch` rejects → `network`;
   - aborted → `timeout`;
   - 2xx with an unparsable body or no text → `bad_response`.
   Exactly one request per call, no retry (sprint decision 6). Base URLs are constants in each adapter.
4. **Register both** in the shipped registry. **Trim `lib/ai/provider-catalog.ts`** to `gemini` and `groq` (sprint decision 5). A test pins that the catalogue ids equal the registry ids.
5. **`/admin/ai` follows the catalogue.**
   - It now lists two providers. A stored `openrouter` or `mistral` shows the existing translated unknown-provider notice.
   - Add PA-6b: a test where the deps factory or `getDb()` throws, and the page and the action return the translated error without exception text (Sprint 5 audit W3).
   - The "chat not available yet" note stays until US-028.
6. **`.env.example`, README, `lib/ai/env-example.test.ts`:** only `GEMINI_API_KEY` and `GROQ_API_KEY`, each with a one-line comment naming where to create the key. README "Environment variables" says they are needed for the chat (US-028) and are set in Vercel, never in the app.
7. **Fixtures:** under `test/fixtures/ai/`, hand-written JSON bodies that follow each provider's public API reference. For each provider: a success body, a body with no candidates/choices, and an error body. Also (tech-lead, 2026-09-26): a Gemini invalid-key body (400, `API_KEY_INVALID`), a 404 unknown-model body for each provider, and a Groq `json_validate_failed` body. A short `README.md` states that they were written from the documentation, not recorded with a key.

## Acceptance criteria (DRAFTED BY AGENT — PO to confirm)

- **AC1** — Gemini request. A mocked `fetch` records the call. It is one `POST` to the Gemini `generateContent` URL for the configured model (URL-encoded). The key appears only in the `x-goog-api-key` header, and the URL contains no key. The body carries the system text, the user text and the output-token limit. JSON mode sets `responseMimeType` to `application/json`. (FR6; AGENTS.md secrets rule; sprint decisions 1 and 5)
- **AC2** — Groq request. One `POST` to the Groq chat-completions URL, with `Authorization: Bearer <key>`. The body carries `model`, a system message and a user message, and `max_tokens`. JSON mode sets `response_format` to `json_object`. The URL contains no key. (FR6; sprint decisions 1 and 5)
- **AC3** — Responses. For each adapter:
  - the committed success fixture gives `{ ok: true, text }` with the fixture's text;
  - the fixture with no candidates/choices gives `bad_response`;
  - a non-JSON 200 body gives `bad_response`.
  (FR6; sprint decision 1)
- **AC4** — Errors never leak.
  - For each adapter, status 401, 403, 404, 429 and 500, a rejecting `fetch` and an aborted signal map to `auth_failed`, `auth_failed`, `model_not_found`, `rate_limited`, `provider_error`, `network` and `timeout`.
  - Gemini: the committed 400 `API_KEY_INVALID` fixture maps to `auth_failed`, and a 400 without that reason maps to `provider_error`. Groq: the committed 400 `json_validate_failed` fixture maps to `bad_response`. (Tech-lead amendment, 2026-09-26.)
  - No case throws.
  - With a sentinel key, and an error body that echoes that sentinel, no result contains the sentinel, the URL or any part of the response body.
  (AGENTS.md secrets rule; DEC-015 point 1; sprint decision 1)
- **AC5** — One request, no retry. Every case in AC1–AC4 makes exactly one `fetch` call. Through `runGeneration`, a request that never answers ends as `timeout` at the US-025 constant (fake timers). (FR6; sprint decision 6)
- **AC6** — Catalogue equals the implemented providers. `PROVIDER_CATALOG` holds exactly `gemini` and `groq`, the shipped registry holds exactly the same ids, and a test pins the equality. `.env.example` lists exactly the two key variables, and `env-example.test.ts` follows the catalogue. (FR6 "the exact set of supported providers is to be validated at implementation time"; FR11 "from the list of supported free ones"; sprint-05 decision 10; sprint decision 5)
- **AC7** — `/admin/ai` follows the catalogue.
  - Render tests in `ro` and `en` show the two providers in the select and in the key table.
  - A stored `mistral` shows the translated unknown-provider notice, and the page does not crash.
  - PA-6b: when the deps factory or `getDb()` throws, the page and the save action return the translated error, with no exception text.
  (FR11; sprint-05 decision 10; Sprint 5 audit W3; AGENTS.md secrets rule)
- **AC8** — Interchangeable by settings alone. With `settings` pointing at `gemini` (model and key stubbed), the wiring module plus `runGeneration` calls the Gemini URL. Switching `settings` to `groq` calls the Groq URL instead. There is no code change between the two, and each case makes one `fetch` call. (FR6 "easy to swap"; EPIC-06 "two interchangeable free providers")
- **AC9** — Offline and gates.
  - No test reaches a provider: `fetch` is always mocked or injected.
  - No SDK dependency is added.
  - `pnpm typecheck`, `pnpm lint`, `pnpm test` and `pnpm build` pass. The build also passes with `DATABASE_URL` and both key variables unset.
  (AGENTS.md "Tests never call … AI providers", Commands; sprint decision 1)

## Notes for verification

- **Fixtures come from documentation.** The reviewer compares the request bodies and fixture shapes with each provider's public API reference as the implementer cites it in the plan (URL and field names), and does not assume them. What a live provider really returns is proven only by the user's manual QA.
- **Model in the Gemini path.** The model sits in the Gemini URL path, and `ai_model` is free text written by an open admin form (requirements §6). `encodeURIComponent` keeps it from adding path segments or a query string. Add a test with a model such as `../x?key=y`.
- **Key placement.** The Gemini API also accepts `?key=` in the URL. It must not be used: URLs end up in logs and error objects.
- **Catalogue trim.** The trim changes existing US-022 tests that assumed four providers. Update them to follow `PROVIDER_CATALOG`, not to a new hard-coded list, so the tests still check the page against the catalogue.

## Tech-lead review 2026-09-26

Approved for planning, with one real defect in the draft fixed in place (Task 3, Task 7 and AC4 are marked):

1. **Wrong-key status for Gemini.** The draft mapped only 401/403 to `auth_failed`. The Gemini API answers a request with an invalid key with HTTP **400** (`status: "INVALID_ARGUMENT"`, `details[].reason: "API_KEY_INVALID"`), not 401. With the draft mapping, sprint-06.md manual QA step 7 ("the AI provider rejected the key") would fail for Gemini and show a generic provider error. The adapter now reads the parsed error body's `reason` field to classify a 400. Reading a code field is allowed; the body text, URL and key still never enter a result (AC4's sentinel case covers the new branch too: the invalid-key fixture used in the sentinel test echoes the sentinel).
2. **`model_not_found`.** Sprint decision 1 (amended) adds this code. Both providers answer an unknown model with 404 (Gemini `NOT_FOUND`, Groq `error.code: "model_not_found"`). The model is free text (decision 4), so this is the likeliest user error and gets its own reply in US-028.
3. **Groq JSON mode.** When JSON mode cannot produce valid JSON, Groq answers 400 with `error.code: "json_validate_failed"`. That is a model-output problem, so it maps to `bad_response`, not `provider_error`. US-027 passes it on as `provider_error` with code `bad_response` (its AC8), and US-028 words that reply as "try rephrasing", not as a provider fault.
4. **Documentation, not assumption.** The plan cites the provider documentation page for each of these error shapes (as "Notes for verification" already asks for request shapes), and the fixture README says so. If the documentation the planner finds disagrees with points 1–3, the documentation wins and the plan says why.
5. **Gemini thinking models.** Gemini 2.5 models spend "thinking" tokens from `maxOutputTokens`. A small limit can end with `finishReason: "MAX_TOKENS"` and no text part, which correctly maps to `bad_response`. The adapter does not work around it; US-027 sets a generous limit (see its review).
