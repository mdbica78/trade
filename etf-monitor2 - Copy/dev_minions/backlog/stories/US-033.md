# US-033 — Diagnosable load failures and schema-drift visibility
> Detailed by the Technical Lead chat, 2026-09-28 — PO to confirm at demo.

**Sprint:** 8 · **Epic:** EPIC-07 · **Depends on:** US-032 · **Binding text:** `decisions/DEC-019-load-error-telemetry-and-schema-drift.md` §1–§3
**Suggested model / thinking:** strong model, high thinking. Complex (a loader fallback, `/health` change, many pages, 7 ACs) → `story-planner`: "plan US-033".

## Context
- The live home page shows only "Could not load the data." (US-016 AC9: the exception is never rendered). The cause cannot be told
  apart: `DATABASE_URL` missing, migration `0001_etf_report_links.sql` not applied on Neon, Neon cold start, a real bug.
- `lib/monitoring/home.ts` `buildLatestReportLinksStatement` does `left join "etf_report_links"` (US-030, DEC-018 §4). On a
  database without that table the whole home batch fails.
- `/health` (`lib/health.ts`) counts `etfs` and `field_catalog` only, so it reports "connected" with a schema that is behind.
- Loaders in scope: every `app/**/page.tsx` whose `try/catch` renders an error state. Find them with a search for `catch` under
  `app/` (known: `app/page.tsx`, `app/etf/[symbol]/page.tsx`, `app/chat/page.tsx`, `app/admin/**/page.tsx`); the plan lists them all.
- AGENTS.md secrets rule; FR13 "silent failures are defects"; requirements §4.

## Task
1. `lib/log/load-error.ts`: `describeLoadError` and `logLoadError` exactly as DEC-019 §1 (walk `cause` up to 3 levels; `code` only
   `^[0-9A-Z]{5}$`; `relation` only `^[a-z_][a-z0-9_]*$`; never message, stack, query, params, anything with `://` or the
   `DATABASE_URL` value). Unit tests with a sentinel connection string in the message, the cause and the stack.
2. Call `logLoadError("<page scope>", error)` in every catch found above. The HTML is unchanged.
3. `lib/health.ts`: DEC-019 §2. Tables derived from the schema exports with `getTableName`; one `to_regclass` statement; inside the
   existing 8 s race. `HealthStatus` connected member gains `schema`; `app/health/page.tsx` renders a translated "schema out of date,
   run `pnpm db:migrate`" line with the missing identifiers (RO and EN, `Health.*` keys), and nothing extra when the schema is current.
4. `lib/monitoring/home.ts`: DEC-019 §3, confined to `etf_report_links` + SQLSTATE `42P01`. Add the reports-only variant of the
   statement; the plan names the exact seam (the batch runner). Log through Task 1's helper.
5. `README.md` "Deployment": order is **migrate, then deploy**, plus the read-only check
   `select to_regclass('public.etf_report_links');` (null means apply `pnpm db:migrate`).

## Acceptance criteria (DRAFTED BY AGENT — PO to confirm)
- **AC1** — Safe log line. `describeLoadError` on a Drizzle-style wrapper (`cause` holds a driver error with `code: "42P01"` and a
  message containing `postgres://user:SENTINELPW@host/db`) returns `{ name, code: "42P01", relation: "etf_report_links" }` and
  nothing else. `logLoadError` prints one line starting `[load-error]`. The line contains none of: the sentinel password, `://`,
  the error message, a stack frame. A `code` of any other shape and a `relation` with a space, quote or dot are dropped, not printed.
  (DEC-019 §1; AGENTS.md secrets rule)
- **AC2** — Pages log but do not leak. For each page found in Task 2, a test with `getDb()` (or the loader) throwing an error that
  carries the sentinel: the rendered HTML equals today's generic error state (no code, no name, no sentinel) and a
  `console.error` spy received exactly one `[load-error]` line for that page's scope, without the sentinel. (US-016 AC9, US-018 AC6, US-028 AC7 stay met)
- **AC3** — `/health` names a stale schema. On PGlite with every migration but the last dropped (or `etf_report_links` dropped),
  the connected page shows the translated schema line and lists `etf_report_links` and only identifiers, in RO and EN; on a fully
  migrated PGlite it shows no schema line. The table list is derived, proven by a test that adds a synthetic table to a schema
  fixture and sees it reported. The 8 s timeout still covers the extra statement (HP-F2 stays green). (DEC-019 §2; FR8.1)
- **AC4** — Home falls back only for the optional join. On PGlite with `etf_report_links` dropped, the home loader returns the
  table with the ETFs' latest values and report-derived links (not the error state) and logs one `[load-error]` line with
  `code=42P01 relation=etf_report_links`. With `reports` dropped instead, or a `42703` error injected, or `42P01` on another
  relation, the loader still returns the error state. With the table present, the result is identical to today's
  (existing `home-links.pglite.test.ts` unchanged and green). (DEC-019 §3; US-030 AC4 unchanged when the table exists)
- **AC5** — No new secret path. A boundary test scans `lib/` and `app/` sources: `console.` calls in page catch blocks go only
  through `logLoadError`; `lib/log/load-error.ts` reads no `process.env`. (AGENTS.md secrets rule)
- **AC6** — Bilingual and gates. `Health.schemaStale`-style keys exist in `messages/en.json` and `messages/ro.json` (the existing
  key-parity test stays green). `pnpm typecheck`, `pnpm lint`, `pnpm build`, `pnpm test` pass with the four variables unset.
- **AC7** — README. "Deployment" states migrate-before-deploy and the `to_regclass` check; a test or grep proves the sentence is present.
  MANUAL-QA (user): after the redeploy, open `/health`; if the schema is behind, it names the table.

## Out of scope
