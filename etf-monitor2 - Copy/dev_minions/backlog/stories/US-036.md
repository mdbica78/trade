# US-036 — Home table look: symbol opens the detail page (whole row clickable), small "PDF" button, no "History" link, delta vs previous available report with arrows, phone scroll wrapper
> Detailed by agent (story-planner), 2026-09-28 — PO to confirm at demo.

**Sprint:** 9 · **Epic:** EPIC-08 · **Depends on:** US-047 (same files, `lib/monitoring/home.ts` and `components/HomeTable.tsx`: strictly after it, never in parallel), US-035 (tokens, the scroll wrapper, the `data-*` hook on the "extraction unavailable" marker), US-017 (delta maths), US-030 (report links, the no-adapter marker)
**Suggested model / thinking:** strong model, high thinking. Complex: a read-model SQL change, the new delta rule, deliberate exact-markup changes, the binding design reference, and the QA render harness of sprint item D-7 (13 ACs). So it is planned by `story-planner`.

  - `lib/monitoring/home.ts`: `buildPreviousDayOkValuesStatement` joins the `ok` report at exactly `report_date - 1`; `computeCellDelta` also checks `previousCalendarDay(valueDate)`. `buildActiveEtfsStatement` does not select `etfs.name`.   - `lib/monitoring/delta.ts`: exact bigint `computeDelta` (absolute and percent, `null` percent on a zero divisor) and `previousCalendarDay`.

## Task

1. **Delta rule (T-2).** In `lib/monitoring/home.ts`:
   - Replace `buildPreviousDayOkValuesStatement` with a statement that returns, per ETF and per `field_key`, the value and `report_date` of the newest `ok` report of that ETF **earlier than** its newest `ok` report that has a non-null `numeric_value` for that field.
   - `computeCellDelta` drops the `previousCalendarDay` comparison. It still returns `null` for a missing or non-canonical current or previous value.
   - Each cell with a delta also carries the previous report's date (`previousDate`), per field.
   - `lib/monitoring/delta.ts`: the exact arithmetic is unchanged. `previousCalendarDay` leaves the production path. The plan says whether it is deleted (then its tests go with it, listed as a deliberate change) or kept as an unused, still-tested helper.
2. **Name in the view model.** `buildActiveEtfsStatement` also selects `etfs.name`, and each `HomeRow` carries `name`.
3. **Row and first cell** (`components/HomeTable.tsx`, spec rule 4, review §2 row-click):
   - The symbol is a `next/link` `Link` to `/etf/<encodeURIComponent(symbol)>` on every row, whether or not a PDF URL is known. It carries the stretched-link hook (a class or `data-*` attribute). The row carries the hook that sets `position: relative`.
   - Next to the symbol: when `latestPdfUrl` is set, a small bordered "PDF" `<a>` (`href` = that URL, `target="_blank"`, `rel="noopener noreferrer"`) with a translated accessible name that names the symbol, and a hook with a higher `z-index` than the stretched link. When no URL is known, no button (P12).
   - Under the symbol: the ETF's full name (`row.name`) in a small muted element.
   - The "extraction unavailable" marker stays, with its US-035 `data-*` hook.
   - The `Home.historyLink` link is removed, and its message key leaves both catalogues.
   - `HomeTable` stays a server-renderable component: no `"use client"`, no `onClick`, no event handler.
4. **Value cells** (spec rule 5, FR7.2, P-2):
   - The value, then **one** change line under it, in the order arrow, absolute, percent. Each part appears only when the column's effective switch (US-047) is on. With all three off, or with `delta: null`, there is no change line.
   - Arrow: `▲` when the absolute change is positive, `▼` when negative, `–` when it is zero (P-2). The arrow has a translated accessible text (e.g. a visually hidden word, or `aria-label`), so the direction is not carried by the glyph and colour alone.
   - Tone: the existing gain/loss/flat hooks, decided from the canonical absolute string, coloured from US-035's `--gain` / `--loss` / `--flat` tokens.
   - The change line's `title` names the previous report's date, formatted per P5 in the page's locale (translated text).
   - A `null` percent (previous value 0) shows no percent part (US-017 AC2, review §2 (4)).
5. **Stylesheet** (`app/globals.css`, hooks and classes only, no positional selectors, DEC-020 §5):
   - the row hover highlight (`--hover`), the stretched `::after` (`position: absolute; inset: 0`), the row's `position: relative`, the PDF button's border, radius (8 px, spec token line), `position: relative` and higher `z-index`;
   - numeric cells: `text-align: right`, `font-variant-numeric: tabular-nums`;
   - date and numeric cells: `white-space: nowrap`; the table keeps US-035's `min-width` inside its scroll wrapper (the phone correction of DEC-020 §10);
   - header labels small, uppercase and `--muted`; row padding and dividers as spec rule 3.
6. **Messages:** the PDF button's accessible name, the arrow's accessible texts (up, down, unchanged), and the change line's `title` text, in both catalogues. `Home.historyLink` is removed from both.
7. **QA render harness (sprint item D-7, recommendation (a); built here because this story owns the final table markup):**
   - A script under `scripts/qa/` (run with the existing `tsx`, e.g. a `qa:render-home` package script) renders the shipped home presentational components (title row, Customize panel open, card, `HomeTable`) with a committed fixture view model into standalone HTML files, one per theme (`data-theme` on `<html>`) and locale, linking the stylesheet produced by `pnpm build`. Output goes outside the repo's tracked tree (e.g. `/tmp/etf-qa-render/`).
   - The fixture view model has at least four ETFs, several value columns, gains, losses, a flat value, a blank cell, one row with no PDF URL, and one no-adapter row.
   - To stay identical to the live page, the harness renders the same presentational component `app/page.tsx` renders. If `app/page.tsx` composes the title row, panel and card inline, the plan extracts that composition into one component with byte-identical output, and says so.
   - If the Customize panel (US-047) cannot render open without a click, the plan adds the smallest prop that opens it initially (default closed, no markup change when unset) and lists it.
   - Nothing under `app/` or `lib/` imports `scripts/qa/`.
   - If the in-loop `tech-lead` picks D-7 option (c) instead, this task is dropped, AC11 no longer applies, and the filled-table captures become one JUDGMENT item in US-039.

## Notes for verification

- **Per-field "previous".** The previous report is chosen per field, not per ETF (T-2). AC4's per-field case is the one that separates a correct statement from "the ETF's previous `ok` report". The reviewer checks the SQL filters on a non-null `numeric_value` for that `field_key` and on `report_date` strictly below the latest `ok` date.
- **Where T-2's test rewrite is allowed.** Only the P6 cases in `home-delta.pglite.test.ts` change meaning. `computeDelta`'s tests must not change at all (AC5). A changed expectation anywhere else in the delta tests is a red flag.
- **`position: relative` on `<tr>`.** Current browsers support it, but it has a history of engine quirks. If the Codex capture shows the stretched link not covering the row, the plan's fallback (e.g. a positioned wrapper inside the first cell, or `transform` on the row to create the containing block) must keep AC1's single-link-per-row structure. The reviewer checks keyboard order: one row link, then the PDF button.
- **The arrow is not the only signal.** The sign in the absolute part and the arrow's accessible text carry the direction, so a colour-blind reader, or a view with only the arrow switched on, still gets it (FR15 "accessible").
- **Tone without floats.** The tone and arrow come from the canonical absolute string (sign and zero check). The reviewer checks no float arithmetic is added to the delta path (`delta.ts`'s scan covers only that file).
- **Harness drift.** The harness must render the same component tree as `app/page.tsx`. The reviewer checks it imports that component and does not re-create the markup.
- **Design reference.** HANDOVER has one line per PNG (four lines). None says MATCH for a part this story does not own.
- **Manual QA (Codex):** run the harness after `pnpm build`, open its HTML files and capture about 1200×560 in light and dark and 390 px wide; also capture the live `/` (empty/error state) through `qa-serve.sh`. Compare with `mockup-home-light.png`, `mockup-home-dark.png` and `mockup-home-phone.png` (AC10). Check row hover, that a click on the PDF button opens the PDF and not the detail page, and that no cell wraps at 390 px (AC8).
