# Sprint 6 — AI natural-language configuration

> Detailed by agent (story-planner), 2026-09-26 — PO to confirm at demo.

**Epic:** EPIC-06
**Status:** see the `status.md` Story board
**Blocked by:** nothing for the agent. Every dependency below is Done or Awaiting QA (AGENTS.md, delivery loop step 1). The sprint is built and verified fully offline: fake providers, `fetch` mocked with committed response fixtures, PGlite. Its **live** checks need things only the user can do: create free accounts with two AI providers, put their API keys into the Vercel project's environment variables, and redeploy (roadmap carry-forward: "API keys are live steps for the user, never handled by agents"). Until then the live steps wait in the QA checklists.

## Goal

Configuration by conversation, provider-agnostic (roadmap, Sprint 6). EPIC-06 "Done when": "configuration commands work in both Romanian and English, against at least two interchangeable free providers."

Concretely:
- A chat in the user area (requirements §5: "User area … plus the conversational interface for quick commands") takes a natural-language command in Romanian or English, such as "add ETF XYZ", "stop tracking ETF ABC" or "also track VUAN for BTBETRETF" (FR1, FR2).
- The chat turns the command into exactly one of the configuration actions the admin forms already perform. It performs that action through the shared `lib/config/` layer (FR9 "both paths (chat and form) operate on the same configuration model"; DEC-016).
- The model behind the chat is the provider chosen in `/admin/ai` (FR6, FR11). Each provider sits behind one adapter interface (FR6 "pluggable — a single AI-provider adapter, easy to swap").
- The chat is one **capability plugin** on top of that interface, not a hard-coded parser (requirements §2.2 design note).
- The AI is used for configuration only (FR5). PDF extraction stays the deterministic parser, and nothing in this sprint touches `lib/extraction/` or `lib/ingestion/`.

## Why this order

- **US-025 first.** It builds the provider layer every other story uses:
  - the adapter interface and its closed error vocabulary;
  - the provider registry;
  - resolving the active provider from `settings` and the key's environment variable;
  - the one sanctioned way for a key value to reach an adapter.
  It changes the `lib/ai` boundary tests on purpose (decisions 1 and 2), so later stories inherit the rule and do not reopen it.
- **US-026 and US-027 after US-025**, in any order or in parallel:
  - US-026 adds two concrete adapters (HTTP, mocked in tests) and trims the provider catalogue to them.
  - US-027 builds the configuration capability. It turns text into one validated configuration intent and runs against a **fake** provider, so it does not need US-026.
  - The two stories touch different files.
- **US-028 last.** It wires everything together: the chat page, a Server Action, executing the intent through `lib/config/`, translated replies, and the "not configured" states. It needs real adapters (US-026) and the capability (US-027). It is also where the Sprint 5 audit's action-boundary test (W2) lands, "before or with the first chat action".

## Sprint Definition of Done

- All four stories reviewed and tested (PASS/PASS), Awaiting QA, then accepted by the user.
- `pnpm test` runs fully offline and proves the following:
  - **Provider layer (US-025).** A provider adapter never throws. Its errors are a closed set. A key value appears in no result, error or rendered HTML (sentinel tests with `vi.stubEnv`). The active provider resolves from `settings` with a translated reason for every "not usable" case.
  - **Adapters (US-026).** Gemini and Groq send the documented request, with the key only in a header, never in the URL. They parse the documented response fixtures, map HTTP and network failures to the closed codes, make exactly one request per call, and are interchangeable through `settings` alone.
  - **Intent extraction (US-027).** RO and EN commands, served by a fake provider, become exactly one validated intent. Malformed, off-scope, multi-action or ungrounded model output becomes `unclear` or `unsupported`, never an action. Interpreting a message writes nothing.
  - **Chat (US-028).** It performs the four actions only through `lib/config/`. The home-table and daily-job loaders follow (PGlite, shipped statements). Every reply is a translated template. An unconfigured provider makes no network request. No page or reply contains exception text, a key or an environment value.
- No test calls a live AI provider, Neon or bvb.ro. Global `fetch` is mocked or injected in every AI test (AGENTS.md).
- `lib/config/` still imports nothing from `lib/ai/` (DEC-016 §1, BC-1). Every Server Action passes the new action-boundary test (decision 14).
- No AI SDK or other runtime dependency is added (decision 1). If a plan finds one necessary, it is justified in the plan and installed with an exact version.
- Every UI string is in both `messages/ro.json` and `messages/en.json`, and the key-parity test passes (FR8.1).
- `pnpm typecheck`, `pnpm lint`, `pnpm build` pass, and `pnpm build` passes with `DATABASE_URL` and every provider key variable unset.
- **No schema change.** Chat history is not stored (decision 13), and every column written already exists. If a plan finds one necessary, the migration is generated locally with `pnpm db:generate` and applied to Neon only by the user (AGENTS.md).
- The user has run the live checks below and answered the PRODUCT items above.

## Manual QA the user must perform in this sprint

Needs the deployed app with `DATABASE_URL` set. Everything below involves your accounts, your API keys or your Neon data, so it is yours. Agents never create accounts or handle keys (AGENTS.md "Hand back to the user"). The Codex QA loop can check the offline and locally served parts: with no database or no provider configured, `/chat` shows a translated notice instead of the composer and makes no request.

1. **Accounts and keys (US-026).** Create a free API key with Google AI Studio (Gemini) and one with Groq. In the Vercel project → Settings → Environment Variables, add `GEMINI_API_KEY` and `GROQ_API_KEY` (Production), then redeploy. Open `/admin/ai`. Only Gemini and Groq are listed, both show "set", and no key value appears anywhere on the page.
2. **Choose a model (US-025/US-026).** In `/admin/ai`, pick Gemini and type a current free model name from Google's model list, then save. Open `/chat`. The composer is available, not the "not configured" notice.
   - Clear the model and save. `/chat` now asks you to choose a model (decision 4). Put the model back.
   - Type a model name that does not exist and save. A chat command gets the translated "the provider does not know this model" reply (`model_not_found`, decision 1). Put the model back.
3. **Commands in Romanian (US-027/US-028).** With the UI in RO, send each command below, then check the home page.
   - "Adaugă ETF-ul ICBETNETF": it appears in `/admin/etfs`, with adapter "none" (no adapter exists for its format). ICBETNETF is not seeded, but if you already added it through the form, the reply says it is already monitored: use any BVB fund unit that is not monitored yet.
   - "Nu mai urmări ICBETNETF": it disappears from the home table.
   - "Urmărește și activul net pentru BTBETRETF": an "Activ net" column appears.
   - "Nu mai urmări activul net pentru BTBETRETF": the column disappears.
   Each reply is in Romanian and says exactly what was done.
4. **Commands in English.** Switch to EN and repeat step 3 in English, for example "add ETF ICBETNETF", "stop tracking ETF ICBETNETF", "also track net asset for BTBETRETF", "stop tracking net asset for BTBETRETF". Replies are in English. "also track VUAN for BTBETRETF" replies "already tracked" while VUAN is tracked (the seed tracks it for every seeded ETF, `lib/db/seed-data.ts`).
5. **Scope and safety.** Send "What is the VUAN of BTBETRETF today?" and "Write me a poem". Each gets the translated "I can only change the configuration" reply, and nothing changes in `/admin/etfs`.
   - Send "add the energy ETF" (no symbol). The reply asks for the symbol, and nothing is added (decision 8).
6. **Swap providers (US-026, EPIC-06 "interchangeable").** In `/admin/ai`, switch to Groq with a current Groq model name. Repeat two commands from step 4: they work the same way.
7. **Failure path.** Temporarily set the chosen provider's key variable in Vercel to a wrong value and redeploy. A chat command returns the translated "the AI provider rejected the key" reply, with no key and no provider error text shown. Restore the key.
8. **Logs.** In Vercel → Logs, check the chat requests from steps 3–7: no API key appears in any log line.
9. **PO confirmation.** Every story in this sprint was drafted by an agent. Confirm or correct the acceptance criteria, and answer the PRODUCT items above (#4, #5, #9, #10, #11, #12). #5 decides which accounts you need. #10 decides what name an ETF added by chat gets.
