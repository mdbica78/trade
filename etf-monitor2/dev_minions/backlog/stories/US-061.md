# US-061 — Professional /admin/ai

Sprint 14. Depends on: none. The user's five Sprint 14 needs are the business requirements; this is BR3.

## Acceptance criteria
- **AC1 (FR11; Sprint 14 BR3):** Replace the provider/key table and repeated key forms with a provider-selected card/menu: provider selector, set/not-set/source status, and write-only key input with Save/Replace/Remove for that selected provider only.
- **AC2 (FR11, FR6; Sprint 14 BR3):** Present custom providers as readable cards showing name, URL, saved model and key status, with per-provider edit/delete and a collapsible add-provider form.
- **AC3 (FR11; DEC-021, DEC-026, DEC-029):** Preserve key lifecycle, provider/model behavior and server validation. Key values remain write-only and are never passed to rendered props, displayed, logged or echoed. Preset and custom models continue to use their provider-specific stored model.
- **AC4 (FR8.1, FR11):** Both locales and both themes are covered; visual changes use existing tokens and maintain WCAG AA. Deliberate changes to admin golden snapshots are identified and refreshed only through a normal verified test run.
- **AC5 (FR8.1, FR11):** Focused UI/action/privacy tests, typecheck, lint, full suite and offline build pass.

## Data / schema impact
No schema change or migration. Reuse `settings.ai_models` (DEC-029/0006), `ai_provider_keys` (DEC-021/0003), and `ai_custom_providers` (DEC-026/0005). UI changes only; keep server-side key handling and key-free `ProviderKeyStatusView`/`CustomProviderView` projections.

## Scope
No provider or key behavior changes, no new provider fields, no client exposure of key material, and no new dependency.
