# US-041 — Provider presets (OpenAI-compatible list) and model picker; no free-form URL (presets only)
> Detailed by agent (story-planner), 2026-10-02 — PO to confirm at demo.

**Sprint:** 10 · **Epic:** EPIC-08 · **Depends on:** US-040 (build sequence and encrypted-key status/wiring); existing US-022, US-025 and US-026 provider catalogue, configuration and adapters  
**Suggested model / thinking:** strong model, high thinking. The story adjusts provider catalogue/registry and `/admin/ai`, and includes a product roster question that must remain PROPOSED.

## Context

- **FR16** requires selecting a provider from presets and entering a model name, without a free-form base URL. A preset must not permit the user to redirect a stored key.
- **DEC-021 §8** binds endpoints to adapter/catalogue code and explicitly forbids custom URLs. Every offered preset must correspond to an implemented adapter and fixed endpoint.
- The current implementation supports Google Gemini and Groq. The roadmap phrase “OpenAI-compatible list” does not name vendors. The binding pre-detail review §4 records **D-1 as PROPOSED / NEEDS USER** and recommends the isolated default of shipping only existing Gemini/Groq presets until additional providers are named.
- **Review §2 US-041** requires static model suggestions per preset, free-text model entry using existing bounded validation, reuse of `settings.ai_provider` / `settings.ai_model`, no live model listing, and a regression test that ignores injected `baseUrl`.
- This story does not create new endpoint support, a new credential store, or new runtime dependencies.

## Task

1. Keep the user-selectable catalogue limited to existing implemented Gemini and Groq presets as the isolated default. Record D-1 as **PROPOSED / NEEDS USER** in this story and Sprint 10 decisions table. Do not add any unnamed provider; any future named addition must have a fixed endpoint and implemented adapter.
2. Keep catalogue IDs aligned with the adapter registry. Keep endpoints fixed in provider adapter/catalogue code and ignore any `baseUrl` field from client form/action input.
3. Add static per-preset model suggestions and a free-text model field using the existing maximum-length validation and `settings.ai_provider` / `settings.ai_model` persistence path.
4. Update `/admin/ai` in Romanian and English. Preserve US-040's write-only key handling; this story must not expose or copy key material.

## Acceptance criteria (DRAFTED BY AGENT — PO to confirm)

- **AC1 — Explicit isolated preset roster.** This story ships exactly the currently implemented Google Gemini and Groq adapters as fixed presets. The story and Sprint 10 table label D-1 **PROPOSED / NEEDS USER**, not Decided; the D-1 prompt asks whether the user wants additional named presets. Naming another vendor alone does not authorize implementation in this story: each additional preset requires an explicitly scoped follow-up that includes its implemented adapter and fixed endpoint. This isolated default does not block delivery. (FR16; DEC-017; DEC-021 §8; Sprint 10 review §4)
- **AC2 — Fixed endpoints and adapter mapping.** Every visible preset ID exists in both the provider catalogue and concrete adapter registry, and resolves only to its implementation-owned endpoint. Tests post/inject a `baseUrl` alongside provider/model data and prove it is ignored: neither persisted settings nor the outbound mocked request target can be controlled by that field. No free-form URL input or custom endpoint is rendered. (FR16; DEC-021 §8; Sprint 10 review §§2–3)
- **AC3 — Model picker without live discovery.** Each shipped preset has static model suggestions available to the UI; users may enter another model as free text within the existing bounded model validation. Selecting a preset/model persists through the current `settings.ai_provider` and `settings.ai_model` configuration functions and reloads as the saved selection. Tests use local static data and mocked/PGlite config dependencies; no provider API is called to list or validate models or credentials. (FR16; DEC-016; DEC-017; Sprint 10 review §2)
- **AC4 — Settings errors, safe key state and bilingual UI.** Invalid/unknown preset and over-length model input produce the established closed configuration errors and do not mutate saved settings. `/admin/ai` shows the selected provider/model and its static suggestions in RO and EN while retaining US-040's write-only behavior: key values never appear in default values, rendered HTML, action results, logs or errors. Message catalogs have matching keys. (FR16; FR8.1; DEC-021 §§5–7)
- **AC5 — Offline boundaries and gates.** Catalogue/registry parity, ignored-`baseUrl`, model validation/persistence, both locales and key-free outputs have automated offline tests using fake keys, mocks and PGlite only. Focused tests and `pnpm typecheck`, `pnpm lint`, `pnpm test`, offline `pnpm build` pass with live database/provider variables absent. No live model discovery, credential validation, provider call, Neon, Vercel, new dependency or arbitrary URL is involved. (FR16; DEC-021; DEC-023; AGENTS.md “Commands” and “Secrets”)

## Out of scope

- Adding a provider not already implemented unless the user names it and a separate scoped implementation is approved; current default is Gemini and Groq only (D-1).
- Custom or free-form base URLs, user-defined endpoints, or endpoints accepted from form/action input (FR16; DEC-021 §8).
- Live model listing or provider credential validation.
- Changes to encryption, stored-key schema, key lifecycle, or key visibility (US-040).
- Chat instructions/capabilities (US-042 / Sprint 11).

## Decisions needed

- **D-1 — PRODUCT, PROPOSED / NEEDS USER:** Does the initial provider preset roster need named providers beyond Google Gemini and Groq? **Isolated default:** the selector uses only the already implemented Gemini and Groq presets until the PO names additional vendors. This default is shipped; no story is blocked. No free-form URL is offered under FR16/DEC-021.
