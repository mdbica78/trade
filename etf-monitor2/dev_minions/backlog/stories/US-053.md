# US-053 — Chat sees the current state; "all ETFs"; clear/update by description
> Detailed by the Technical Lead chat, 2026-10-05. Sprint 13. Binding text: `decisions/DEC-025-chat-understanding.md` (DEC-025 §1-§4). PO to confirm at demo.

**Sprint:** 13 · **Epic:** EPIC-08 · **Depends on:** nothing
**Suggested model / thinking:** strong model, high thinking (AI capability system) → `story-planner` plan.

## Context
The user's chat transcript of 2026-10-05 shows the chat failing on plain requests. Causes and design: the binding DEC above, section "How the chat works today". No user step: any migration rides the deploy (DEC-023).

## Task
1. Extend the prompt data block per ETF with tracked field keys and existing widgets (slot, operation, fieldKey, periodUnit, periodAmount, title). Keep it escaped JSON inside the data tags.
2. Support `"etf":"*"` / `"symbol":"*"` (not for add/remove ETF): expand to all active ETFs before validation; one expanded action counts as one of the 5.
3. `widget_clear` / `widget_update` accept `match` {operation?, fieldKey?, periodUnit?, periodAmount?} instead of `slot`; resolve per ETF; zero matches for one ETF = per-ETF "nothing matched", the others still run.
4. Default scope: no ETF named → all active ETFs. Grounding no longer needs the symbol in the message text when the model returned `*`; a named symbol must still exist.
5. Results are reported per ETF (one result line per ETF for an expanded action).

## Acceptance criteria (confirmed by the PO, 2026-10-05)
- AC1 — Gates: typecheck, lint, build, full test suite and `scripts/claude/predeploy-check.sh` pass; no existing behaviour test is loosened (AGENTS.md); deliberate test changes are listed in HANDOVER with the reason.
- AC2 — Prompt data contains tracked fields and widgets for each ETF; a prompt-injection string stored as a widget title stays inside the data block (escaped) — test.
- AC3 — `*` expands to exactly the active ETFs; 8 active ETFs + one `*` action is accepted (not `too_many`); `*` on add/remove ETF is rejected — tests.
- AC4 — Transcript cases pass with recorded model outputs: "clear max value for units in circulation for last month for all etf" clears exactly the matching widget on each ETF; "clear min value … last 7 days for all etf" likewise; an ETF with no match reports "nothing matched" and the others still clear — PGlite tests.
- AC5 — "add max value for units in circulation for last 7 days" (no ETF) adds the widget to every active ETF (default scope) — test.
- AC6 — Validate-all-first and in-order execution unchanged (DEC-022 §7); existing chat tests green.
- AC7 — (PO, 2026-10-05) "All ETFs" and the default scope mean every ETF saved in the app whose status is active; a deactivated ETF is never included in a `*` expansion or the default scope, and naming a deactivated ETF explicitly gives a specific error, not a silent change — tests.

## Out of scope
New widget operations, code generated by the model, keys in chat.
