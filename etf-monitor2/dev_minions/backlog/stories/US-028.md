# US-028 — Chat surface wired to the configuration actions (RO and EN)
> Detailed by agent (story-planner), 2026-09-26 — PO to confirm at demo.

**Sprint:** 6 · **Epic:** EPIC-06 · **Depends on:** US-026, US-027
**Suggested model / thinking:** mid model, high thinking. Complex: configuration writes through `lib/config/`, a new route and Server Action on an open endpoint, and secrets in every error path (11 ACs). So it is planned by `story-planner`.

## Context

- **FR1, FR2:** add or remove ETFs and choose tracked parameters "via natural-language command".
- **FR5:** the conversational interface is "exclusively for configuration".
- **FR8.1:** RO and EN, "including the conversational interface".
- **FR9:** "both paths (chat and form) operate on the same configuration model".
- **Requirements §5:** the **user area** has "the conversational interface for quick commands ('add ETF X', 'also track VUAN')".
- **FR6, FR11:** the model is the one chosen in the admin area.
- **EPIC-06 "Done when":** "configuration commands work in both Romanian and English, against at least two interchangeable free providers."

What exists:
- **US-025:** `resolveActiveProvider`, `runGeneration`, and the wiring module (settings + key + registry + global `fetch`).
- **US-026:** the Gemini and Groq adapters.
- **US-027:** `interpretConfigurationRequest` → `intent` | `unsupported` | `unclear` (with reason) | `multiple` | `provider_error`, and `loadConfigurationContext`.
- **`lib/config/`** (DEC-016):
  - `addEtf({ symbol, name })` runs adapter detection, reactivates an inactive symbol, and returns `already_monitored` for an active one;
  - `setEtfActive({ symbol, active })`;
  - `trackField({ symbol, fieldKey })`;
  - `untrackField({ symbol, fieldKey })`.
  Each returns a typed result. The deps factories are `createEtfConfigDeps` and the tracked-field deps.
- **Admin pattern:** Server Actions are thin (no SQL). Results map to translated message keys, and exception text is never returned (`app/admin/*/actions.ts`, `result-messages.ts`).
- **`/admin/ai`** still shows "the configuration chat is not available yet" (`Admin.ai.chatUnavailableNote`).
- **Sprint 5 audit W2:** there is no regression guard yet for "Server Actions contain no SQL". It must land "before or with the first chat action" (sprint decision 14).
- **Open access** (requirements §6): no login. The chat, like `/admin`, is reachable by anyone who has the URL.

## Task

1. **Execute step** (DEC-016 §2), e.g. `lib/ai/capabilities/configuration/execute.ts`. It maps a validated intent to exactly one `lib/config/` call and returns a typed outcome that carries the config result:
   - `add_etf` → `addEtf({ symbol, name: name ?? symbol })` (sprint decision 10);
   - `remove_etf` → `setEtfActive({ symbol, active: false })`;
   - `track_field` → `trackField`;
   - `untrack_field` → `untrackField`.
   It contains no SQL. Deps are injected.
2. **Chat entry module**, e.g. `lib/ai/chat.ts`, the one `lib/` module the chat action imports besides `lib/db` (sprint decision 14). It performs one message, in order:
   - validate the message (sprint decision 13: trimmed, non-empty, at most 500 characters);
   - resolve the active provider (US-025);
   - on a "not usable" reason, stop with no network call;
   - load the context, interpret (US-027), execute (step 1);
   - return one typed reply descriptor: a message key plus validated values (symbol, field key, detected adapter, reason).
   It never throws, and no returned value carries exception text, the key or model prose.
3. **Route and page** `app/chat/page.tsx`, with `export const maxDuration = 60` (sprint decision 6). It holds:
   - a client component with a message box and a send button (`useActionState`, as `ActionForm`);
   - a transcript of the user's messages and the translated replies, kept in client state only (sprint decision 13).
   When the provider is not usable, the page shows the translated reason with a link to `/admin/ai` instead of the composer.
4. **Server Action** `app/chat/actions.ts`. It reads one `message` field from `FormData` and calls the chat entry module. After a successful write it revalidates `/`, `/admin/etfs` and the ETF's fields page. It returns a translated reply key and values, and it contains no SQL.
5. **Replies.** A key-to-message map, e.g. `app/chat/reply-messages.ts`. Each is a next-intl template in the UI locale, with the field label taken from the catalogue in that locale. The replies cover:
   - added (with or without a detected adapter) and reactivated;
   - already monitored, removed, ETF not found;
   - tracked, already tracked, untracked, not tracked, field not available;
   - unsupported, unclear (per reason), multiple;
   - empty message, too long;
   - each "provider not usable" reason and each provider error code;
   - a generic error.
6. **Header and admin note.**
   - `components/AppHeader.tsx` gets a `Nav.chat` link to `/chat` (sprint decision 12), and `AppHeader.test.tsx` asserts it.
   - `/admin/ai` replaces the "chat not available yet" note with a translated link to `/chat`.
7. **Action-boundary test** (Sprint 5 audit W2, sprint decision 14). One test scans every `app/**/actions.ts`. It fails on:
   - a `drizzle-orm` import, a `sql\`` template, or `insert into` / `update "` / `delete from` text;
   - any `lib/` import outside `lib/config/*`, `lib/db`, `lib/ai/settings-deps` and the chat entry module.
8. **Messages:** `Chat.*` and `Nav.chat` keys in both catalogues.
9. **Tests:**
   - PGlite end to end with the fake provider: the real entry module, the real `lib/config/` functions, detection mocked. After each action, the shipped home-table and daily-job loaders are re-run (DEC-016 §4).
   - Render tests in `ro` and `en`, sentinel tests, the action-boundary test.

## Acceptance criteria (DRAFTED BY AGENT — PO to confirm)

- **AC1** — Chat page in the user area.
  - `/chat` renders a translated heading, a message input and a send button, in `ro` and in `en`.
  - The header shows a translated `Nav.chat` link to `/chat` next to Home and Administration.
  - The page is dynamic, and its route exports `maxDuration = 60`.
  (Requirements §5 "User area … plus the conversational interface"; FR5; FR8.1; sprint decisions 6 and 12)
- **AC2** — Commands change configuration only through `lib/config/`. In a PGlite test with the fake provider scripted per message (each case starts from the same seeded database):
  - "add ETF XYZ" inserts one `etfs` row through `addEtf` (detection mocked), and the shipped home-table loader then lists `XYZ`;
  - "stop tracking ETF BTBETRETF" sets `is_active = false`: the home-table and daily-job loaders omit it, and its reports and tracked fields are unchanged;
  - "also track net asset for BTBETRETF" adds a `net_asset` tracked field (one BTBETRETF does not track yet), and the home-table columns include it;
  - "stop tracking VUAN for BTBETRETF" removes its `nav_per_unit` tracked field, and its `report_values` stay.
  The execute step and the action contain no SQL (source scan).
  (FR1, FR2, FR9 "both paths (chat and form) operate on the same configuration model"; DEC-016 §§1, 2, 4; sprint-05 decision 4)
- **AC3** — ETF name.
  - "add ETF XYZ" stores `name = 'XYZ'`.
  - A message that contains a name (e.g. "add ETF XYZ named Fond Test") stores that name.
  - Adding an inactive symbol by chat reactivates it and keeps its stored name and adapter, with no detection request.
  (FR1; data model `etfs.name` NOT NULL; sprint-05 decision 4; DEC-016 open item; sprint decision 10)
- **AC4** — Replies are translated templates, never model prose.
  - Every outcome of the execute step and of US-027 maps to a message key present in both catalogues. A test iterates the whole outcome union, not a hand-written list (Sprint 5 audit N4 lesson).
  - A render or action test in `ro` and `en` shows the reply in the UI locale, with the field's catalogue label for that locale.
  - With the fake provider returning valid JSON plus an extra property that holds a sentinel string, the sentinel appears in no reply and no HTML.
  (FR8.1 "including the conversational interface"; AGENTS.md "Every UI string goes through next-intl"; sprint decision 7)
- **AC5** — Every config result is reported. Tests cover each case and its reply key:
  - added with an adapter;
  - added with none ("extraction unavailable" wording, section 3);
  - reactivated;
  - `already_monitored`;
  - remove of an unknown symbol → `not_found`;
  - tracked, already tracked, untracked, not tracked, field not available.
  (FR1, FR2, FR9; section 3 "automatic extraction is marked 'unavailable'"; FR13 spirit, no silent failure)
- **AC6** — Not-configured states make no request. For each resolution reason (`not_configured`, `unknown_provider`, `not_implemented`, `no_api_key`, `no_model`):
  - the page shows its translated message and a link to `/admin/ai`;
  - a submitted message gets the same reply;
  - a `fetch` spy records zero calls, and the database is unchanged.
  (FR6, FR11; sprint-05 decision 10; sprint decision 4)
- **AC7** — Failures never leak.
  - Each provider error code gives its translated reply.
  - A thrown database error (context load or write), a throwing deps factory and a throwing `getDb()` give the translated generic error, in the action and on the page (the page then shows no composer).
  - With every key variable stubbed to a sentinel and an exception message that holds another sentinel, neither sentinel appears in any action result or rendered HTML.
  (AGENTS.md "Secrets … Never commit, log or print one"; DEC-015 point 1; Sprint 5 audit W3 pattern)
- **AC8** — Input limits, one call.
  - An empty or whitespace message, and a 501-character message, are rejected with a translated reply before any provider call (zero `generate` calls).
  - A 500-character message is accepted.
  - A valid message makes exactly one `generate` call and at most one `lib/config/` write call.

- **AC9** — Action-boundary test (Sprint 5 audit W2).

  (FR9; DEC-016 §2; Sprint 5 audit W2; sprint decision 14)
- **AC10** — `/admin/ai` now points to the chat. The "chat not available yet" note is gone, and a translated link to `/chat` replaces it. Render tests in `ro` and `en` pass. (FR11; FR5)
- **AC11** — Bilingual and gates.
  - Every new string is in both catalogues, and the key-parity test passes.
  - No test reaches a provider, Neon or bvb.ro.
  - No schema change, no new dependency.
  - `pnpm typecheck`, `pnpm lint`, `pnpm test` and `pnpm build` pass. The build also passes with `DATABASE_URL` and both key variables unset.
  (FR8.1; AGENTS.md "Tests never call …", Commands)

## Notes for verification

- **Duration budget.** The plan states the worst case against `maxDuration = 60`: one provider call (20 s timeout) plus `addEtf` detection (two requests at `CRON_FETCH_TIMEOUT_MS`, plus PDF text extraction). The reviewer checks that the numbers come from the constants in code.
- **Open endpoint.** The action accepts only `message`. The reviewer checks that no other form field reaches `lib/config/` and that the length check comes before any provider or database call (US-020 notes: "no action accepts a field it does not need").
- **Revalidation.** After a chat change, the home page and `/admin/etfs` must show it without a manual reload of a stale cache. Test this with `revalidatePath` mocked, as the admin actions do.
- **Reply for "added".** The reply says whether an adapter was detected, using the same reason codes as the admin form (`DetectionReason`). This is what makes "adapter missing" visible from the chat path too (section 3; Sprint 7 US-030 note).
- **"Stop tracking" is ambiguous in English.** "stop tracking ETF X" removes the ETF (FR1's own example). "stop tracking VUAN for X" untracks a field. The model is told both forms in the prompt (US-027), and the reply always says which of the two was done, so a misreading is visible and reversible (sprint decision 11).
- **Manual QA (live, user):** sprint-06.md steps 2–8.

## Tech-lead review 2026-09-26

Approved for planning. AC7 was clarified in place (the page, not only the action, handles a throwing `getDb()`/deps factory). Points for the plan:

1. **Key-free availability for the page.** `resolveActiveProvider` succeeds with an object that carries `apiKey` (US-025). The page must not receive that object: it calls a key-free availability function (reason, or provider id + model) from the chat entry module or the US-025 wiring module (US-025 review point 3). AC7's sentinel test renders the page in the `ok` state as well as the failure states.
2. **Which config results are reachable.** US-027's grounding pre-empts most `lib/config/` errors: `remove_etf` of an unknown symbol is `unclear`/`unknown_etf`, an already tracked field is `unclear`/`already_tracked`, an untracked field is `unclear`/`not_tracked`, a field outside the adapter is `unclear`/`unknown_field`. The matching config results (`not_found`, `already_tracked`, `not_tracked`, `field_not_available`) are reached only when the database changes between interpretation and execution. So:
   - AC5's cases that grounding pre-empts are proven at the execute step with a constructed intent (or a database changed after the context load), and the plan says which;
   - a grounding reason and its matching config result give the **same** reply wording (e.g. both "already tracked" paths), so the user sees one answer for one situation.
3. **Reply wording for the provider codes.** `model_not_found` points to Administration → AI ("check the model name"); `bad_response` asks the user to rephrase; `auth_failed` says the provider rejected the key (sprint-06.md step 7). None shows provider text.
4. **Removing an inactive ETF.** `setEtfActive(false)` on an ETF that is already inactive returns `ok` (`lib/config/etfs.ts`). The reply must still be true ("… is not monitored"), not "removed" as if it had been active. Either reply is acceptable if the plan states it and a test pins it.
5. **Action-boundary test.** Settled in sprint decision 14: case-insensitive text patterns; `@/lib/…` and relative specifiers both matched (today's four actions import `@/lib/db`, `@/lib/config/*`, `@/lib/ai/settings-deps`); one synthetic self-check per forbidden pattern. With `app/chat/actions.ts` there are exactly five action files, so AC9's "at least five" holds only once this story's action exists.
6. **Open endpoint cost.** Anyone with the URL can spend the user's free-tier quota (requirements §6: no login). The 500-character limit bounds each request; rate limiting stays out of scope. The demo lists this for the user as information, not as a blocker.
