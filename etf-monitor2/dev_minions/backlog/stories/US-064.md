# US-064 — Daily job time applied by Vercel itself (no GitHub ping)

Sprint 14. Depends on: US-062 (gate and claim stay), DEC-031 (Decided, conditional on spike S1). Replaces US-062 AC3 and AC4.

User need (2026-10-12): the time chosen in `/admin/cron` must be saved in the system and applied by Vercel, with no GitHub Actions.

## Acceptance criteria
- **AC0 (spike S1, user-run after the first push):** build log shows `[vercel.ts] daily cron hour <h> UTC (source: db)` and Vercel → Settings → Cron Jobs lists `/api/cron/daily` with `0 <h> * * *`. If not, the story is BLOCKED and the Technical Lead chooses Plan B or C (DEC-031). Agents never claim this passed.
- **AC1:** `buildDailyCron(hour)` returns `{ path: "/api/cron/daily", schedule: "0 <hour> * * *" }` for integer 0–23 and throws `RangeError` otherwise; the path equals `DAILY_CRON_PATH`.
- **AC2:** `resolveBuildCronHour` in `lib/config/cron-build.ts` (relative imports only) follows DEC-031 §2: valid stored hour; NULL, invalid or missing row gives 10; missing table (42P01) gives 10; production plus query failure retries 3 times and then throws; non-production or no `DATABASE_URL` gives 10 without any network call; the connection string never appears in logs or error messages. Query function and environment are injected.
- **AC3:** `vercel.ts` exists at the project root, builds `crons` from AC1 and AC2, uses no new dependency; `vercel.json` is deleted; no other config file exists. `lib/config/cron.ts` no longer imports `vercel.json` (remove `effectiveSchedule` and `findDailySchedule`; keep `parseDailySchedule` only if still used). `lib/cron/vercel-config.test.ts` is rewritten to test the `vercel.ts` export (single once-a-day entry for `/api/cron/daily`, hour from the injected resolver) and the README contract.
- **AC4:** `requestRedeploy` in `lib/config/cron-apply.ts` POSTs `VERCEL_DEPLOY_HOOK_URL` with an injectable `fetch` and a 10 s timeout, and returns `applying | not_configured | failed`. It is called only when the saved hour changed. The URL is never logged, thrown, returned or rendered; errors are mapped to the closed result.
- **AC5:** `saveCronHourAction` saves first, then calls `requestRedeploy`; a hook failure never undoes or hides the save. Three new result messages, Romanian and English, appear in the form state.
- **AC6:** `/admin/cron` drops the ping, rule and safety-net sections and shows: the saved hour with its Bucharest equivalent, the Hobby window sentence (DEC-031 §6), the "active in about 2 minutes after a redeploy" note, the earlier-hour-means-tomorrow note, and the last run. All strings in `messages/ro` and `messages/en`.
- **AC7:** `.github/workflows/daily-ping.yml` deleted. README: remove the ping and repository-secret steps, add the Deploy Hook step (DEC-031 §7). `.env.example` gains `VERCEL_DEPLOY_HOOK_URL` with a comment; the env-example test is updated to match. The root-level copy `etf-monitor2-daily-ping.yml` sits outside the project folder: agents list it in HANDOVER as "user deletes"; they do not attempt it.
- **AC8:** Regression: the daily route, handler, gate (`not_scheduled_hour`), atomic claim and their tests are unchanged and pass. Add one test: an early request after a saved later hour still returns `skipped` with no `job_runs` write (redeploy window).
- **AC9:** typecheck, lint, full suite and offline build pass. Offline `next build` must not import or run `vercel.ts`.

## Data / schema impact
None. No migration. `settings.cron_hour_utc` already exists.

## Scope
No minute selection, no weekdays, no Vercel REST API token (Plan B only if S1 fails), no Pro-plan change. No agent runs git, deploys, or reads secrets (DEC-015).

## User steps (once)
1. Vercel → Settings → Git → Deploy Hooks: create one on the production branch; add its URL as Production env var `VERCEL_DEPLOY_HOOK_URL`.
2. Commit and push; check AC0 in the build log and Settings → Cron Jobs.
3. Delete the repo-root `etf-monitor2-daily-ping.yml`; the GitHub secrets can be removed.
