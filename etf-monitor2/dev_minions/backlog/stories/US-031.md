## Task

1. **Whole-pipeline test** (sprint decision 11a), e.g. `test/e2e/daily-pipeline.pglite.test.ts`:

2. **Deployment smoke script** (sprint decision 11b), `pnpm smoke:deploy <baseUrl>`: pure logic in a tested module, plus a thin CLI under `scripts/`. The script:

   - never calls the cron route or a Server Action, and never reads an environment variable;

   - exits non-zero on any failure.
3. **`/health` hardening** (Sprint 1 audit W4, W6):

## Acceptance criteria (DRAFTED BY AGENT — PO to confirm)

- **AC1** — The whole pipeline, offline. One test drives `handleDailyCron` with `Authorization: Bearer <sentinel>` over PGlite (every migration + seed) and the mocked `fetch`, and asserts all of the following:
  - HTTP 200, with one final `job_runs` row whose status, counts and per-ETF log lines match each ETF's expected outcome;
  - for each seeded BRD ETF, one `ok` report whose `report_date` comes from the PDF's own footer (not from the page's filing stamp), and whose tracked values equal `test/fixtures/expected.json`, never the adapter's own output;
  - for the no-adapter ETF: no `reports` row, a stored link (US-030), and `no_adapter` in the log;
  - for ICBETNETF: the end state of US-029's branch (an `ok` report, or `no_adapter`);
  - the shipped home loader shows those values, links and markers; the history loader shows one row per ETF with a report; the operations read models list the run and the "adapter missing" flag;
  - the sentinel `CRON_SECRET` and a sentinel `DATABASE_URL` appear in no response body and no `job_runs.log`.
  (FR3, FR4, FR7, FR8, FR13; section 3; EPIC-07; data model "Write rules"; DEC-010; AGENTS.md secrets rule)
- **AC2** — Re-run and a missing day.
  - A second run over the same fixtures gives `already_ingested` for each ETF that already has an `ok` report. Row counts in `reports` and `report_values` are unchanged, and no `ok` row changes (DEC-010).
  - A run in which one ETF's page has no report entries gives `missing` for it: no row for that day, and the other ETFs are unaffected.
  - The home table keeps showing that ETF's last `ok` values, with their own date.
  (FR4.1 "that day remains blank … no automatic retries"; data model "an `ok` row is never downgraded"; US-014 AC2; US-016 AC3)
- **AC3** — Deployment smoke script. Unit tests with a mocked `fetch` prove each of these rules:
  - only GET requests are sent, and only to the given origin. A redirect to another origin is a failure and is not followed;
  - the page list contains no `/api/` path, and no request carries an `Authorization` header or any cookie other than `NEXT_LOCALE`;
  - a page passes only with HTTP 200, `<html lang>` equal to the requested locale, and none of the page's translated error-state texts. Those texts are read from `messages/<locale>.json`, not hand-written;
  - a 500, a timeout (named constant) or a wrong `lang` gives a failing line and a non-zero exit code. All pages passing gives exit 0;
  - a response body holding a sentinel string never appears in the output;
  - the script reads no `process.env` value (source scan);
  - the base URL must be `https`, or `http://localhost` / `http://127.0.0.1` for a locally served app.
  (AGENTS.md "Never … deploy", secrets rule "Never print a variable's value"; requirements §6 open access; FR8.1; sprint decision 11b)
- **AC4** — `/health` survives the likely failures (Sprint 1 audit W4, W6).
  - With `getDb()` throwing `MissingDatabaseUrlError`, the real `loadHealthStatus` path renders the translated failure state and does not throw.
  - With a query that never settles, `getHealthStatus` resolves to the failure state after a named timeout constant (fake timers, no real wait).
  - The success path is unchanged.
  - What the failure state shows follows sprint decision 12's default, unchanged from US-006 AC2. The timeout gives a fixed message that contains no connection detail.
  (US-006 AC2 "renders a clear error state and returns HTTP 200"; Sprint 1 audit W4, W6; carry-forward "Any sprint"; sprint decision 12)
- **AC5** — Chart tooltip wiring (Sprint 4 audit W3). A test renders `FieldChart` and captures the `content` that is actually passed to Recharts' `Tooltip`. It calls that `content` with an active payload for one point, in `ro` and in `en`. The output is the formatted report date plus `formatNumber` of the stored string: e.g. `54.1373` reads `54,1373` in `ro` and `54.1373` in `en`. An inactive or empty payload renders nothing. (US-019 AC3; DEC-007; FR8.1; Sprint 4 audit W3)

  (Sprint decision 11c; AGENTS.md "Delivery loop" step 7; DEC-013)

## Notes for verification

- **Report date vs page date.** The page fixtures (2026-09-23) list newer filings than the PDF fixtures (2026-09-21). The mocked `fetch` serves a fixture PDF for the discovered URL. The stored `report_date` must then be the PDF's own footer date, which proves the "never the filing stamp" rule end to end. The plan states the URL-to-fixture map.
- **Which wiring is real.** The reviewer checks that the pipeline test calls the shipped handler, job runner, ingestion, discovery, download, `extractPdfText` and adapters, and replaces only the database runner and `fetch`. A test that swaps in fake ingestion does not meet AC1.
- **Fetch guard.** The mocked `fetch` throws on any URL outside the fixture map, and the test asserts that no call was rejected. This is the evidence that nothing reached the network (Sprint 6 audit W1–W3 lesson on fetch-guard evidence).
- **Smoke script safety.** The reviewer reads the page list and the request builder: GET only, no `/api/`, no `Authorization` header, no body printed, no `process.env`. The script is safe to point at production because it only reads public pages, as any visitor would (requirements §6: no login).
- **Timeout value.** The `/health` timeout is a named constant well under `maxDuration`. The plan states the number and why (a Neon cold start after sleep, requirements §4).
- **If US-029 is FALLBACK or Blocked.** AC1 covers ICBETNETF by whatever US-029 shipped. If US-029 is Blocked, this story waits for it (sprint table). It does not drop the ICBETNETF case.

APPROVED, no in-place change needed. Decision #11 is settled in `sprint-07.md` (with the redirect rule below); #12 ships its default (`NEEDS USER`). Binding points for the plan:

1. **Seams.** `lib/cron/default-deps.ts` builds `createDailyRunDeps()` / `createDefaultJobRunStore()` on `getDb()`. Any injection point added for AC1 takes an optional runner/db and leaves the no-argument production path unchanged; the existing `lib/cron/default-deps.test.ts` and `lib/ingestion/default-deps*.test.ts` pass unedited. The pipeline test stubs `CRON_SECRET` and `DATABASE_URL` to sentinels (so `readEnv` redaction sees them) and asserts `getDb` is never reached.
2. **Fetch guard evidence.** The mocked `fetch` records every call; the test asserts the recorded list equals the expected URL/method sequence and that the "unknown URL" branch was hit zero times (Sprint 6 audit W3). It also counts requests per ETF against `MAX_REQUESTS_PER_ETF` (DEC-018 §5).
3. **Smoke script.** Requests use `redirect: "manual"`; any 3xx is a failing line (AC3 "a redirect to another origin is a failure" — a same-origin redirect is also reported, not followed, so the page list must name final paths). The plan lists, per page, which `messages/*.json` keys are its failure states (database read errors, `/health`'s `dbUnreachable`). A legitimately unconfigured state, such as `/chat` with no key set, is not a page failure; say how it is reported. The ETF detail page uses a seeded symbol (`BTBETRETF`).
4. **`/health` timeout.** A named constant, well under `maxDuration` (60 s) and above a Neon wake-up of a few seconds; state the number and why. The timed-out query is not awaited afterwards. AC4's `getDb()`-throws test renders the real page component (`loadHealthStatus` is not exported), with only `getDb` mocked, so removing the catch would fail it (Sprint 1 audit W4).
5. **If US-029 is Blocked**, this story is not eligible (dependency), exactly as the Notes say. Do not start it with a stand-in ICBETNETF case.
