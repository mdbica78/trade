# US-023 — Admin: cron hour setting
> Detailed by agent (story-planner), 2026-09-26 — PO to confirm at demo.

**Sprint:** 5 · **Epic:** EPIC-05 · **Depends on:** US-020, US-013
**Suggested model / thinking:** mid model, medium thinking. Complex (cron/infra, changes a Sprint 3 contract test, 9 ACs), so it is planned by `story-planner`.

## Context

FR12: "Cron configuration: view/adjust the time of day the daily extraction job runs. (Note: the free Vercel Hobby plan allows a single cron job per day — not freely configurable frequency, only the time of day can be adjusted within that limit.)" Requirements §4: Vercel Cron on Hobby runs "once per day".

What exists:
- `vercel.json` has one cron entry, `/api/cron/daily`, schedule `0 10 * * *` (US-013; Sprint 3 decision 3, chosen as the initial schedule "before US-023 makes the hour adjustable"). README "Daily ingestion (cron)" says Hobby may fire anywhere within the scheduled hour, and "Until US-023 ships an admin setting for the hour, change it by editing the schedule in `vercel.json` and redeploying."
- `lib/cron/vercel-config.test.ts` pins the schedule to `"0 10 * * *"` ("change together with README").
- `settings.cron_hour_utc` (data model) exists, NULL today. The data model says how it reaches Vercel is this story's open question.
- **Carry-forward note:** "the cron schedule lives in `vercel.json` and changes only on redeploy (Vercel Hobby). The story must say how `settings.cron_hour_utc` reaches Vercel (FR12)."

**How the setting reaches Vercel** (sprint decision 11, isolated default). The app cannot rewrite its own `vercel.json`, and no agent deploys or runs git (AGENTS.md). So the admin page stores the **desired** hour, shows the **effective** schedule (the `vercel.json` bundled into the running deployment), and, when they differ, shows the exact line to change and says the change takes effect after the next Production deployment. The user edits `vercel.json`, commits and pushes. The alternatives (Vercel API or deploy hook, which need a Vercel token; an external scheduler, which needs a new service) are in the sprint table, not in this story.

## Task

1. **Configuration layer**, `lib/config/cron.ts` (same rules as `lib/config/etfs.ts`):
   - `parseDailySchedule(schedule)`: `{ minute, hour }` for a once-a-day expression (`M H * * *`), or `null` for anything else;
   - `effectiveSchedule()`: from `vercel.json`, imported so the bundler embeds it at build time (the file is not on disk inside a Vercel function). The entry is found by its path `/api/cron/daily`;
   - `getCronHour()` / `setCronHour(hour | null)`: reads and writes **only** `settings.cron_hour_utc`, with an upsert on `id = 1` that leaves every other column unchanged;
   - `suggestedScheduleLine(hour)`: the exact `vercel.json` text, `"schedule": "0 <hour> * * *"`.
2. **Page** `app/admin/cron/page.tsx` plus an admin nav entry:
   - effective schedule: "once a day, <HH>:00–<HH>:59 UTC" (Hobby precision, README), or a translated "unrecognised schedule" message if `parseDailySchedule` returns null;
   - desired hour: a select of 0–23 (UTC) plus "not set", preselected from `cron_hour_utc`, and save;
   - when a desired hour is set and differs from the effective hour: a translated notice with `suggestedScheduleLine(hour)` and "then commit, push and wait for the Production deployment". No notice when they match or when nothing is set;
   - a translated note: one run per day (Hobby, FR12), the hour is in UTC, and the change applies from the next Production deployment.

   The Server Action is as in US-020 (no SQL, no exception text).
3. **Contract test and README.** The value pin in `lib/cron/vercel-config.test.ts` (`"0 10 * * *"`) was the Sprint 3 initial default, "before US-023 makes the hour adjustable". Remove that value-pin test. The file already has a shape test ("the schedule is a once-a-day schedule", minute and hour single numbers in range, the rest `*`); keep it, and keep every other `vercel.json` check (one entry, path, no other top-level key except the optional `$schema`). README "Daily ingestion (cron)": replace the "Until US-023 ships…" line with the procedure (set the hour in `/admin/cron`, copy the shown line into `vercel.json`, commit, push), and stop hardcoding `0 10 * * *` as the only schedule. Keep the reason for the default and the Hobby precision note.
4. **Messages:** new `Admin.*` keys in both catalogues.
5. **Tests:** pure tests for `parseDailySchedule` and `suggestedScheduleLine`. PGlite tests for `setCronHour`/`getCronHour`. A test that `effectiveSchedule()` equals the schedule parsed from the repository's `vercel.json` read with `fs`. Render tests in `ro` and `en` for: match, mismatch, not set, unrecognised schedule.

## Acceptance criteria (DRAFTED BY AGENT — PO to confirm)

- **AC1** — View the effective time. The page shows the daily schedule of the running build as an hour window in UTC (for `0 10 * * *`: `10:00–10:59 UTC`). A test proves the value comes from `vercel.json`: it reads the file with `fs`, parses it, and compares it to `effectiveSchedule()`. A schedule that is not once a day shows a translated "unrecognised schedule" message, never a guessed hour. (FR12 "view … the time of day the daily extraction job runs"; requirements §4 "once per day"; README Hobby precision; AGENTS.md "Never guess a value")
- **AC2** — Adjust the desired hour. Saving an integer hour 0–23 sets `settings.cron_hour_utc`. Saving "not set" stores NULL. A PGlite test sets `ai_provider`, `ai_model` and `default_locale` first and finds them unchanged. With no `settings` row, saving creates row `id = 1`. Any other input (text, 24, -1, a decimal) returns a validation error and writes nothing. (FR12 "adjust"; data model `settings.cron_hour_utc`)
- **AC3** — How the change reaches Vercel is stated. When the desired hour is set and differs from the effective hour, the page shows the exact line `"schedule": "0 <H> * * *"` and says the change takes effect after committing it to `vercel.json` and the next Production deployment. When they are equal, or no hour is set, there is no notice. Render tests cover all three cases. (FR12 note "only the time of day can be adjusted within that limit"; carry-forward note "must say how `settings.cron_hour_utc` reaches Vercel"; decision 11)
- **AC4** — Nothing else changes at runtime. Saving makes no network request (no Vercel API, no deploy hook), writes no file, and does not change the running job's schedule. The cron route (`/api/cron/daily`) does not read `cron_hour_utc`. A boundary test checks that `lib/config/cron.ts` imports no network or `fs` module. (ADR-001 "Vercel Hobby, one cron job per day"; AGENTS.md "Never … deploy, … change Vercel settings"; decision 11)
- **AC5** — Still one daily job. `vercel.json` still has exactly one cron entry for `/api/cron/daily`, with no other top-level key except the optional `$schema` (present today). Its schedule is `M H * * *` with M in 0–59 and H in 0–23 (the existing shape test). The value pin `0 10 * * *` is removed and that shape test stays, because FR12 makes the hour adjustable (Sprint 3 decision 3 was the initial default "before US-023"). (FR12; requirements §4; US-013 AC5; Sprint 3 decision 3)
- **AC6** — README. README "Daily ingestion (cron)" describes the admin procedure (set the hour, copy the line into `vercel.json`, commit, push, Production only) and no longer says "Until US-023 ships…". The existing README checks in `vercel-config.test.ts` still pass. (FR12; US-013 AC8)
- **AC7** — Bilingual. Every string (window, notices, notes, select labels, errors) goes through next-intl with keys in both catalogues, and the key-parity test passes. Render tests in `ro` and `en` show the locale's text and not the other's. The `vercel.json` line is shown verbatim in both. (FR8.1)
- **AC8** — Failure states. A database read error still shows the effective schedule (it needs no database) and a translated message in place of the desired hour. A failing save returns a translated error. Neither contains exception text or an environment value. (AGENTS.md secrets rule; US-020 AC9 pattern)
- **AC9** — Gates. No test connects to Neon or Vercel. `pnpm typecheck`, `pnpm lint`, `pnpm test` and `pnpm build` (with `DATABASE_URL` unset) pass, and the build embeds `vercel.json` without a runtime file read. (AGENTS.md Commands; ADR-001)

## Out of scope

- Changing the schedule without a redeploy, calling the Vercel API, deploy hooks, or an external scheduler (decision 11).
- More than one run per day (FR12 note; Hobby).
- Choosing the minute, or showing the hour in Bucharest time (it shifts with daylight saving; the column is UTC).
- Advice on which hour is best. The reason for the 10:00 UTC default stays in the README.
