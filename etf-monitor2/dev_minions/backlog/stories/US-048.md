# US-048 — Migrations applied by the production deploy
> Detailed by the Technical Lead chat, 2026-09-28 — PO to confirm at demo. Binding text: `decisions/DEC-023-migrations-applied-by-the-deploy.md`.

**Sprint:** 9 (first story) · **Epic:** EPIC-07 · **Depends on:** nothing
**Suggested model / thinking:** mid model, medium thinking. Small (one script, one `package.json` line, one guard test, docs) → plan it yourself (≤15 lines).

## Context
- The live app shows "Could not load the data." most likely because `drizzle/0001_etf_report_links.sql` was never applied on Neon. The user does not want any manual `pnpm`/Neon step; a `git push` must be enough (DEC-023).
- `package.json` today: `"build": "next build --webpack"`, `"db:migrate": "drizzle-kit migrate"`. `drizzle.config.ts` reads `DATABASE_URL` from the environment. `tsx` is already a devDependency.
- AGENTS.md: agents never run anything against Neon or Vercel; they write files only.

## Task
1. `scripts/migrate-on-deploy.ts` as DEC-023 §1-§3: skip (one line, exit 0) unless `VERCEL_ENV === "production"` and `DATABASE_URL` is non-empty (unset in production: visible warning, exit 0); otherwise run `drizzle-kit migrate` as a child process (same command as `db:migrate`), up to 3 attempts with a short pause, exit non-zero on failure. Output goes through a small pure function that keeps only the SQLSTATE code (`^[0-9A-Z]{5}$`) and a migration file name (`^\d{4}_[a-z0-9_]+\.sql$`); it never prints the child's raw output, the URL or the message. The environment is passed to the child; the script logs no variable.
2. `package.json`: `"build": "tsx scripts/migrate-on-deploy.ts && next build --webpack"`. `db:migrate` stays as is (the user may still use it; nothing requires it).
3. Guard test over `drizzle/*.sql` (DEC-023 §4): fails on `DROP`, `RENAME`, `ALTER COLUMN ... TYPE` or `NOT NULL` added without `DEFAULT`, unless the file carries `-- allow-destructive: DEC-XXX`. It passes on today's `0000` and `0001`.
4. `README.md` "Deployment" (replaces US-033 AC7's order): "push to the production branch; the build applies pending migrations; check `/health`". `/health`'s translated schema line (RO and EN) drops the `pnpm db:migrate` wording and says the next production deploy applies it. AGENTS.md line about DB migration on Neon is already updated by the Technical Lead; do not change it.

## Acceptance criteria (DRAFTED BY AGENT — PO to confirm)
- **AC1** — Never touches a database outside production. With the environment stubbed: `VERCEL_ENV` unset, `preview`, or `development` → exit 0, the child process is not started (spy), one "skipped" line. Production without `DATABASE_URL` → exit 0, a warning line, no child.
- **AC2** — Production with a database runs exactly `drizzle-kit migrate` once on success; on a failing child it retries up to 3 times and then exits non-zero (fake child and fake clock, no real database, no real sleep).
- **AC3** — Safe output. With a child that prints `postgres://user:SENTINELPW@host/db` and a driver message, nothing printed by the script contains the sentinel, `://` or the message; a SQLSTATE `42P01` and a file name `0001_etf_report_links.sql` in the child's output appear as `code=42P01 file=0001_etf_report_links.sql`; an invalid code or file name is dropped.
- **AC4** — `package.json` `build` is exactly as in Task 2 and `pnpm build` locally (no `VERCEL_ENV`) succeeds without a database, printing the skip line. A test pins the script string.
- **AC5** — Guard test (Task 3) passes on the current migrations and fails on synthetic fixtures for `DROP TABLE`, `RENAME COLUMN`, `ALTER COLUMN x TYPE`, and `ADD COLUMN y integer NOT NULL` without default; the marker exempts a fixture.
- **AC6** — Migrations prove themselves on PGlite: a test applies `drizzle/*.sql` in journal order to an empty PGlite and the schema matches `lib/db/schema.ts` table by table (extends the existing pglite test helpers if they already do this; do not weaken any).
- **AC7** — Docs and text: README "Deployment" states the push-only flow (a grep test); both message files' schema line contains no `pnpm db:migrate`; key parity test stays green.
- **AC8** — `pnpm typecheck`, `pnpm lint`, `pnpm build`, `pnpm test` pass with `DATABASE_URL`, `CRON_SECRET`, `VERCEL_ENV` unset. Denied or attempted commands are reported (DEC-015); no command is run against a real database.

## Out of scope
Rollback tooling, destructive migrations, running migrations at request time, a Vercel or Neon token in any script, preview-database branching.

## Manual QA
None required. Observation after the user's next push: Vercel build log shows the script's one line; `/health` shows no schema line; the home page loads.
