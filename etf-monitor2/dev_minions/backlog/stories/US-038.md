# US-038 — Charts: type selector (line, dots, columns, area), palette, single-point display
> Detailed by agent (story-planner), 2026-09-28 — PO to confirm at demo.

**Sprint:** 9 · **Epic:** EPIC-08 · **Depends on:** US-035 (token palette `--chart-1..6`, `FieldChart` already on tokens), US-019 (the charts)
**Suggested model / thinking:** mid model, high thinking. One component plus a small pure module, but 8 ACs, so it is planned by `story-planner` (CLAUDE.md complexity rule).

## Context

- **FR8.2** (decided 2026-09-28): "Charts let the user choose the type per chart (line, line with dots, columns, area) and use a readable palette. A chart with a single data point still shows that point clearly."
- **Sprint 9 review §2 US-038** is the minimum: (1) a per-chart type selector with line, line with dots, columns and area, default line; (2) the choice remembered per viewer in `localStorage` (try/catch), not on the server; (3) a chart with one point shows a clear point (dot, larger radius, value label); (4) palette from tokens only (DEC-020 §4); (5) missing days still break the line (P11 unchanged).
- **DEC-020 §4:** `FieldChart` reads its colours from the tokens, through `style` props, with no colour literal; "US-038's chart types … and the single-point display use the same palette". **§6:** this story may change exact markup only for the chart wrapper.
- **What exists** (after US-035):
  - `components/EtfDetail.tsx` (server-renderable) renders one `<section data-chart-field="<fieldKey>">` per tracked field, and inside it a `<div data-chart-container>` with `FieldChart` when the series has a value (`hasAnyValue`), else `EtfDetail.noFieldData`.
  - `components/FieldChart.tsx` is a `"use client"` component. It uses Recharts `LineChart` / `Line` (`type="linear"`, `connectNulls={false}`, a dot on every stored day), `CartesianGrid`, `XAxis`, `YAxis`, `Tooltip` with the exported `ChartTooltipContent`. It receives only plain props (`points`, `locale`, pre-translated `labels`) and uses no next-intl, and its colours come from `var(--chart-1)`, `var(--line)`, `var(--muted)`, `var(--panel)` (US-035).
  - `lib/monitoring/chart-series.ts` builds one point per calendar day with `value: null` / `display: null` on a gap day (US-019, P11).
  - `lib/format/chart.ts` formats axis ticks and the tooltip (DEC-007, P5), from the stored `display` string.
  - Tests mock Recharts and capture props (`components/FieldChart.test.tsx`), including the tooltip-wiring tests FC-TT1..FC-TT4 (US-031). There is no DOM test environment; interactive logic lives in pure modules (the `components/chat/chat-state.ts` and US-035 theme-module pattern).
- Recharts 3.10.1 already ships `ComposedChart`, `Bar`, `Area`, `Line` and `LabelList`, so no new dependency is needed.
- Product default **P-4** (line; remembered per browser only). Flagged item **D-6** (what "line" draws): "line" draws no per-day dots except a point with no neighbour on either side; "line with dots" draws a dot on every point.

## Task

1. **Chart-type module** (a pure module, e.g. `components/chart-type.ts`):
   - `CHART_TYPES = ["line", "lineDots", "columns", "area"]` (or equivalent ids), `DEFAULT_CHART_TYPE = "line"` (P-4).
   - A parser: a stored value that is not one of the ids gives the default.
   - The storage key for one chart (per ETF symbol and field key, flagged item D-8 below), and read/write helpers over an injected storage object, each inside try/catch. A throwing storage gives the default on read and is ignored on write.
   - The single-point and isolated-point rules as pure functions over `ChartPoint[]`: "exactly one value in the series", and "this point has a value and neither neighbour has one" (D-6).
2. **`FieldChart`:**
   - A type selector per chart: a labelled control (e.g. a radio group or a `<select>`) with the four types, labels passed in pre-translated, as today's `labels`.
   - One chart body per type, on a single Recharts container (e.g. `ComposedChart`), keeping today's axes, grid, tooltip and `ChartTooltipContent`:
     - **line:** `Line` with `connectNulls={false}`, no dot on a point that has a neighbour, a dot on an isolated point (D-6);
     - **line with dots:** the same line with a dot on every point that has a value;
     - **columns:** `Bar` with one column per day that has a value, none on a gap day;
     - **area:** `Area` with `connectNulls={false}`, filled from the series token.
   - Single point (exactly one value): in every type, that value is drawn as a dot with a larger radius than the normal dot, with a value label showing the stored `display` formatted per DEC-007 for the locale (in columns mode the column is drawn too).
   - Colours: every series stroke, fill, dot and label uses `var(--chart-1)` (and other `--chart-n` / `--muted` / `--panel` tokens), through `style` or colour props, never a literal. Fill transparency is a numeric opacity prop, not a colour.
   - First render (server and first client render) uses the default type. After mount, the component reads the stored choice and switches to it. A change stores the new choice.
3. **`EtfDetail`:** passes each chart its storage identity (the ETF symbol and the field key) and the translated type labels. Only the chart wrapper markup changes (DEC-020 §6).
4. **Messages:** the selector's accessible name and the four type names, in both catalogues.

## Notes for verification

- **Hydration.** The server has no `localStorage`, so the server render and the first client render must both use line. The stored choice applies only after mount, which may show line for a moment. The reviewer checks there is no hydration mismatch path (no storage read during render).
- **Single point vs isolated point.** "Single point" = exactly one value in the whole series (AC4: larger dot plus label, every type). "Isolated point" = a value with a gap on both sides in a longer series (D-6: keeps a normal dot in line mode). The tests cover both, and a series whose first or last point is isolated.
- **Value label text.** It must come from `display` through `formatNumber`, like the tooltip (US-019 AC3), not from `value`. The reviewer checks the label formatter's input.
- **Mocked Recharts.** The mock in `FieldChart.test.tsx` must also capture `Bar`, `Area` and `LabelList` (and the container used). Adding mocks is fine; changing an existing expectation is not (AC6).
- **Manual QA (Codex):** `qa-serve.sh` serves no database, so `/etf/<symbol>` shows its error state and no chart. Codex's checks of this story are therefore the automated gates plus a `raw` fetch showing the page still renders in both locales. The chart visuals are a `LIVE-DB` item for the user (optional): on a real deployment, switch one chart to columns and reload; it stays columns while the other charts stay line, and a field with a single stored day shows a large labelled dot.
