# US-042 — Chat page instruction area (RO and EN)
> Detailed by agent (story-planner), 2026-10-02 — PO to confirm at demo.

**Sprint:** 10 · **Epic:** EPIC-08 · **Depends on:** US-028 (existing chat page and supported configuration capability); US-040 (build sequence and `/admin/ai` key-management destination)  
**Suggested model / thinking:** mid model, medium thinking. Static localized guidance with content/scope tests; no AI integration or data-model change.

## Context

- **FR17** requires an instruction area on the chat page listing supported requests, in Romanian and English.
- The binding Sprint 10 pre-detail review §2 US-042 requires static localized text, tests that the advertised request set matches the currently supported capability, and omission of future FR18/FR19 functionality.
- DEC-021 §9 says the chat never handles keys; a request to set a key gets a fixed response pointing to `/admin/ai`. Any key-management hint in this area must direct the user there and must not invite sending key text into chat.
- Every UI string uses next-intl in both languages (FR8.1). Rendering the instructions needs no provider call.

## Task

Add a static instruction area to the existing `/chat` page. Explain only the configuration requests the currently shipped chat capability supports, localize every string through next-intl in Romanian and English, and direct provider-key setup to `/admin/ai`. Do not add input or behavior that accepts, displays, stores or forwards keys.

## Acceptance criteria (DRAFTED BY AGENT — PO to confirm)

- **AC1 — Localized instruction area.** The chat page presents a clearly labelled static instruction area in both Romanian and English, with each string supplied by matching next-intl message keys. Render tests prove locale-specific content appears in the correct page and translation-key parity holds. (FR17; FR8.1; Sprint 10 review §2 US-042)
- **AC2 — Advertised capabilities match what ships.** The listed requests correspond only to configuration actions currently supported by the shipped chat capability; tests map every displayed example/category to a supported request and reject unsupported claims. Do not advertise Sprint 11 FR18 programmable history widgets, FR19 raw-field extraction, or any unimplemented action. (FR17; FR6; Sprint 10 review §§2–3)
- **AC3 — Key guidance and privacy.** If the instruction area mentions provider keys, it directs setup/replacement to `/admin/ai` and explicitly does not ask users to paste a key into chat. The instructions contain no key input, form field, secret-bearing data, or dynamic content from a key. Existing fixed chat reply behavior for key-setting requests remains unchanged. Tests verify the instruction area introduces no key-entry field or key-bearing content and does not change the existing key-setting reply path. (FR17; FR16; DEC-021 §9; Sprint 10 review §2)
- **AC4 — Static, offline rendering.** Rendering the instruction area in RO and EN uses no AI/provider request and does not change chat action or provider wiring. Tests mock page data where needed and assert zero provider/network calls. Focused tests and `pnpm typecheck`, `pnpm lint`, `pnpm test`, offline `pnpm build` pass without database/provider access. (FR17; DEC-021 §9; AGENTS.md “Architecture rules” and “Commands”)

## Out of scope

- Changes to supported chat capabilities or the AI prompt/parser (US-027/028).
- FR18 programmable history widgets or FR19 raw-field extraction (Sprint 11).
- Accepting, echoing, storing or forwarding provider keys in chat; key management remains `/admin/ai` (DEC-021 §9).
- Live provider/credential checks or new dependencies.

## Decisions needed

None. The supported-request boundary is the existing shipped configuration capability; future Sprint 11 features are explicitly excluded.
