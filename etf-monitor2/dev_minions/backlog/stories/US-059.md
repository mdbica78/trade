# US-059 — Chat answers "list …" requests

Sprint 14. Depends on: none. The user's five Sprint 14 needs are the business requirements; this is BR1, with the cited FRs providing the existing product and language constraints.

## Acceptance criteria
- **AC1 (FR5, FR13; Sprint 14 BR1):** The model can answer requests in Romanian and English to list active and inactive ETFs, tracked fields per ETF, custom values/widgets per ETF, and each ETF's latest successful report date. It answers from supplied context. There are no deterministic list commands, new actions, writes, or unsupported report-value answers.
- **AC2 (FR5, FR13; Sprint 14 BR1):** The prompt context contains only the data needed for those answers, distinguishes active/inactive ETFs, and identifies the latest successful report date per ETF. The existing data-block escaping and prompt-size protections remain effective.
- **AC3 (FR8.1; Sprint 14 BR1):** Chat help gives concise examples of the new list questions in both locales.
- **AC4 (FR5, FR8.1; Sprint 14 BR1):** Offline fixture-driven tests cover every list category in both locales through a fake provider, assert grounded context/reply behavior and no action execution, and do not call a live provider.
- **AC5 (FR5, FR8.1):** Existing tests remain intact; focused tests, typecheck, lint, full suite and offline build pass.

Manual-QA: after deploy, use a configured provider to ask for each list category in both Romanian and English; check answers against current settings and the operations dashboard. This is a model-quality check only.

## Data / schema impact
No schema change or migration. Add a read-only configuration-layer projection of the latest `reports.status = 'ok'` report date per ETF. Reuse the existing tracked-field and widget readers; do not query SQL from `lib/ai/` or send key material to the model.

## Scope
No server-side command parser, action, data-value query, or write. The model continues to answer natural-language requests from its prompt context, as directed by the user.
