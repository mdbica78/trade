# US-024 — Admin: operational dashboard (job runs, last successful extraction, parse errors)
> Detailed by agent (story-planner), 2026-09-26 — PO to confirm at demo.

**Sprint:** 5 · **Epic:** EPIC-05 · **Depends on:** US-020, US-014, US-015
**Suggested model / thinking:** strong model, high thinking. Complex (a change to the ingestion outcome vocabulary, a log parser coupled to US-015's format, three read models, 11 ACs), so it is planned by `story-planner`.

## Context

FR13: "Operational visibility: history of cron runs (success/failure), last successful extraction per ETF, parsing errors (especially useful for ETFs without a matching adapter, cf. section 3)." Requirements §5: "the admin panel only flags that an adapter is missing (FR13)." FR8.1: the interface is in Romanian and English.

What exists:
- `job_runs` (US-015): `started_at`, `finished_at` (NULL for a run swept as stale), `status` (`running` | `success` | `partial` | `failed`), `etfs_processed`, `errors_count`, `log`. The log is text written by `formatRunLog` / `formatAbortedRunLog` (`lib/ingestion/job-run-summary.ts`) and the stale-run sweep (`lib/ingestion/job-runs.ts`, `STALE_RUN_LOG_LINE`):
  - first line `<status>: <N> processed, <M> errors`;
  - then one line per ETF, `<SYMBOL> <code> [<YYYY-MM-DD>] <detail>`, with secrets redacted and the detail truncated to 300 characters;
  - an aborted run has `run aborted: <message>` instead of ETF lines;
  - a swept run gets `did not finish (timed out or crashed)` appended.
- Outcome codes (`lib/ingestion/outcome.ts`, closed list): `ok`, `already_ingested`, `missing`, `fetch_error`, `no_adapter`, `parse_error`, `persist_error`. The run loop adds `internal_error` (`lib/ingestion/run-daily.ts`).
- `reports`: an `ok` row is complete. A `parse_error` row can carry the values found (Sprint 3 decision 5) and an `error_message`. Failures without a PDF date write no row and appear only in `job_runs.log` (Sprint 3 decision 4). The home table, deltas, history and charts show `ok` rows only (product decision P4). **This dashboard is where `parse_error` reports become visible** (carry-forward note).
- **Sprint 3 audit N4 (carry-forward: "fix before the dashboard displays these codes"):** `ingestEtf` maps a *throwing* `registry.get` to `no_adapter` (`ingest-etf.ts` lines 83–91), and its outer catch around `ingestReport` (lines 132–140) labels failures `persist_error` although `ingestReport` cannot reject. The dashboard would show an internal fault as "adapter missing" or "database write failed".
- Sprint 4 formatters: `formatNumber` (DEC-007), `formatReportDate` (P5), `i18n/request.ts` `timeZone: "Europe/Bucharest"`. Reads use `db.execute(sql…)` + `BatchRunner`, tested on PGlite (carry-forward note).

## Task

1. **Fix N4 first** (sprint decision 12), in `lib/ingestion/`:
   - add `internal_error` to `INGEST_OUTCOME_CODES` and to the `IngestOutcome` union (one definition; `run-daily.ts` reuses it instead of declaring its own);
   - a throwing `registry.get` → `internal_error`. `no_adapter` stays only for a NULL or unregistered `adapter_key`;
   - the outer catch around `ingestReport` → `internal_error` (kept as a defensive net, correctly labelled). `persist_error` stays only where a store call fails (`persist()`);
   - update the tests that pin the old labels or the old list (`ingest-etf.test.ts` IE-6c, the `registry.get throws` case and the `Record<IngestOutcomeCode, …>` trigger map in `ingest-etf.failures.test.ts`, and `outcome.test.ts` OC-8a, which pins the seven-code list with `toEqual`), and add a trigger for `internal_error`;
   - while in `ingest-etf.failures.test.ts`, make IF-8c independent of test order (Sprint 3 audit N5; carry-forward "fix when the file is next touched").
2. **Log parser**, `lib/admin/run-log.ts` (sprint decision 13): `parseRunLog(log: string | null)` returns the summary (optional: a run swept while its log was still NULL has only the stale line), then entries `{ kind: "etf", symbol, code, reportDate?, detail }`, `{ kind: "aborted", detail }`, `{ kind: "stale" }`, or `{ kind: "unparsed", text }`. It never throws and never drops a line. A code outside the known list is kept as its raw text.
3. **Read models**, `lib/admin/operations.ts`, each a statement run through a `BatchRunner`:
   - **runs:** every `job_runs` row, newest `started_at` first (decision 15);
   - **per ETF:** every ETF (active and inactive, by symbol) with `isActive`, `adapterAvailable` (key set and registered, the US-016 AC5 rule), and its **last successful extraction**: the newest `ok` report's `report_date` and `fetched_at`, or none;
   - **parse errors:** every `reports` row with `status <> 'ok'`, newest `report_date` first, with symbol, status, `error_message`, `source_url`, and its stored `report_values` (field label from the ETF's own adapter's catalogue entry for the locale, `field_key` if none, as on the history page).
4. **Formatter** `lib/format/datetime.ts` (decision 16): a timestamp in Europe/Bucharest, 24-hour, `ro` `22.09.2026 13:03`, `en` `2026-09-22 13:03`. The read models hand timestamps over as ISO strings with an offset, so neon-http and PGlite behave the same.
5. **Page** `app/admin/operations/page.tsx` plus an admin nav entry, with three sections:
   - **Runs:** start and end time (a translated "did not finish" when `finished_at` is NULL and the status is not `running`; a `running` row shows no end time, only its translated status), translated status, processed and error counts. Each run's log is shown as translated lines: symbol, translated outcome, report date (P5 format), and the detail verbatim under a translated label (decision 14). Aborted and stale lines get translated labels. Unparsed lines are shown verbatim;
   - **ETFs:** symbol, active state, a translated "adapter missing" flag when the adapter is not available (requirements §5), last successful extraction (report date plus fetch time) or a translated "never";
   - **Parse errors:** symbol, report date, translated status, `error_message` verbatim, a link to the PDF (`source_url`, new tab) when present, and the stored values formatted with `formatNumber` (DEC-007).

   Empty states per section, and a translated error state that never renders exception text.
6. **Messages:** `Admin.*` keys in both catalogues for every run status, every outcome code (including `internal_error`), every report status, and the page text.
7. **Tests:** unit tests for the N4 fix. Parser tests, including a round trip over `formatRunLog`, `formatAbortedRunLog` and a stale-swept log. PGlite tests for the three read models. Formatter tests. Render tests in `ro` and `en`.

## Acceptance criteria (DRAFTED BY AGENT — PO to confirm)

- **AC1** — Outcome codes are truthful (N4). A `registry.get` that throws gives `internal_error`, never `no_adapter`. An error escaping `ingestReport` gives `internal_error`, never `persist_error`. `no_adapter` is returned only for a NULL or unregistered `adapter_key` (IF-1a/IF-1b unchanged), and `persist_error` only when a store call fails (IE-4 unchanged). `internal_error` is in the closed code list, the trigger-map test covers it, and `summarizeRun` counts it as an error. IF-8c passes when run alone (`-t IF-8c`). (FR13; section 3 "flags that an adapter is missing"; Sprint 3 audit N4, N5; carry-forward note)
- **AC2** — Run history. The page lists every `job_runs` row, newest first, with start time, end time (or "did not finish" for a finished-status row with NULL `finished_at`; none for a `running` row), translated status, `etfs_processed` and `errors_count`. A PGlite test with a `success`, a `partial`, a `failed`-and-swept (NULL `finished_at`) and a `running` row shows all four correctly. (FR13 "history of cron runs (success/failure)"; data model `job_runs`; US-015; decision 15)
- **AC3** — Log lines translated. `parseRunLog` returns, for the output of `formatRunLog` with every outcome code (with and without a report date), exactly the symbols, codes, dates and details that went in. ("Details" means the detail as `formatRunLog` wrote it: one line, redacted, truncated to 300 characters.) It also handles `formatAbortedRunLog` output, a log with the stale line appended, a log that is only the stale line (a run swept while its log was NULL), a NULL log, and a line it cannot parse (kept as `unparsed`, verbatim). Render tests show each code's translated text in `ro` and `en`, the detail verbatim, and an unknown code as its raw text. (FR8.1; FR13; data model write rule "`job_runs.log` holds per-ETF outcome codes"; decisions 13, 14)
- **AC4** — Last successful extraction per ETF. Every ETF is listed with the `report_date` and `fetched_at` of its newest `ok` report. A newer `parse_error` row does not count. An ETF with no `ok` report shows "never". An inactive ETF is listed and marked inactive. (FR13 "last successful extraction per ETF"; P4)
- **AC5** — Adapter missing is flagged. An ETF whose `adapter_key` is NULL or not in the adapter registry carries a translated "adapter missing" flag. A test covers both, next to an ETF with `brd-depositary`. (Requirements §5 "the admin panel only flags that an adapter is missing (FR13)"; section 3; FR13 "especially useful for ETFs without a matching adapter")
- **AC6** — Parse errors visible. Every `reports` row whose status is not `ok` is listed with symbol, report date, translated status and `error_message`. The PDF link (`source_url`) opens in a new tab when present, and is absent, never built, otherwise. Its stored values are shown with their field labels in the DEC-007 format. A PGlite test stores a `parse_error` report with one value and `error_message = 'missing fields: nav_per_unit'`, and finds both on the page. `ok` rows are not listed. (FR13 "parsing errors"; product decision P4 "errors go to the admin dashboard"; Sprint 3 decision 5; DEC-007; AGENTS.md "Never guess a value")
- **AC7** — Dates, times and numbers. Report dates use `formatReportDate` (P5). Timestamps use `formatDateTime` (decision 16), whose unit tests cover both locales, a summer and a winter timestamp (UTC+3 / UTC+2), the days daylight saving starts and ends (2026-03-29, 2026-10-25), and independence from the process time zone. Values use `formatNumber`. (DEC-007; P5; Sprint 4 decision 4; FR8.1)
- **AC8** — Bilingual. Every string goes through next-intl with keys in both catalogues, and the key-parity test passes. There is a message key for every code in `INGEST_OUTCOME_CODES` and every `job_runs.status`, checked by a test that iterates the code list. Render tests in `ro` and `en` show the locale's text and not the other's. (FR8.1; AGENTS.md "Every UI string goes through next-intl")
- **AC9** — No leak, no crash. Log text and error messages are rendered as text: a test with `<script>` in a log detail finds it escaped. When a read throws, the page shows a translated error and contains no exception text or environment value. The page shows only what is stored (the log is already redacted by US-015) and adds nothing from the environment. (AGENTS.md secrets rule; data model write rule "`job_runs.log` … never secrets"; US-016 AC9 pattern)
- **AC10** — Shipped statements, offline. The three read models are tested on PGlite with `drizzle/0000_init.sql`, executing the statements the page runs. No test connects to Neon. The dashboard writes nothing. (Carry-forward note "Reuse the read layer from Sprint 4"; AGENTS.md "Tests never call live Neon")
- **AC11** — Gates. `pnpm typecheck`, `pnpm lint`, `pnpm test` and `pnpm build` (with `DATABASE_URL` unset) pass. (AGENTS.md Commands)

- A report link for no-adapter ETFs (US-030).

## Notes for verification

- **Changing Sprint 3 tests is intentional here.** IE-6c and the "registry.get throws" trigger currently expect `no_adapter`. AC1 changes that expectation to `internal_error`, as the Sprint 3 audit (N4) and the carry-forward note require. OC-8a (`outcome.test.ts`) changes from seven codes to eight. The reviewer checks that no other expectation changed, and that IF-1a/IF-1b (`no_adapter`) and IE-4/IE-6b-iii (`persist_error`) are untouched. This is a behaviour correction with a cited source, not a weakened test.
- **Log-format coupling.** The parser depends on US-015's line format. The round-trip test must call the real `formatRunLog` / `formatAbortedRunLog` and use `STALE_RUN_LOG_LINE`, not hand-written strings, so a future format change fails here first. Symbols contain no spaces (US-020 decision 5), which keeps the first token unambiguous. Older rows written before `internal_error` existed parse the same way.
- **Timestamps.** Neon HTTP returns `timestamptz` as a string, and PGlite may return a `Date`. Normalise in SQL (e.g. `to_char(... at time zone 'UTC', …)` or an ISO string) or in one helper, and test both shapes, as `home.ts` does for dates (Sprint 4 audit N7).
