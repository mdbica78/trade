# Demo — US-064

## 1. What changed

US-064 replaces the GitHub Actions hourly-ping schedule (US-062 AC3/AC4) with a Vercel-native cron
schedule (DEC-031). The daily job's hour is now baked into `vercel.ts` at build time (read from
`settings.cron_hour_utc`, default 10), and saving a new hour from `/admin/cron` triggers a Vercel
Deploy Hook so the new schedule takes effect automatically, about two minutes later, with no
GitHub Actions workflow and no manual redeploy.

## 4. Your steps (live, cannot be done by an agent)

1. Vercel → Settings → Git → Deploy Hooks: create one on the production branch. Add its URL as
   the Production environment variable `VERCEL_DEPLOY_HOOK_URL`.
2. Push this branch.
3. Open the new deployment's build log and confirm a line reading
   `[vercel.ts] daily cron hour <h> UTC (source: db|default)`.
4. Open Vercel → Settings → Cron Jobs and confirm it lists `/api/cron/daily` with schedule
   `0 <h> * * *`, matching the hour in step 3. If it does not match, **do not try to fix it
   yourself** — tell the agent so `tech-lead` can pick DEC-031's Plan B or C.
5. Optionally, from `/admin/cron`, save a different hour and confirm the result message and that
   a later build log/Cron Jobs listing reflects the new hour (about two minutes after saving).
6. Delete the repo-root workflow copy `../.github/workflows/etf-monitor2-daily-ping.yml` (outside
   this project folder). Optionally also delete the now-unused GitHub repository secrets
   `ETF_MONITOR_BASE_URL` / `CRON_SECRET` (the Vercel environment variable `CRON_SECRET` itself
   must stay — it is still used by the cron route's bearer check and by key encryption).
