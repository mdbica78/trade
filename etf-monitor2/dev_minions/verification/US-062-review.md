### Findings

**Notes (non-blocking):**
1. `app/api/cron/daily/route.test.ts` has no dedicated test for the two `skipped` bodies; the route is a one-line delegate and the shape is proven at handler level (GT-1/GT-4) and through the real handler in e2e DP-4. Adequate for AC5.
2. `bucharestTimeOfUtcHour` renders the equivalent for *today's* date; around a DST switch the label for the saved hour can differ by one hour from the following day. Acceptable (UTC is the stored/gated truth and the page says so); the explanatory text could mention it later.
3. The workflow's `curl --show-error` may print the target host on failure; the value is a repository secret, which GitHub masks. Optionally drop `--show-error` to be strict.
4. The handler calls `deps.now()` for the hour check and `runDailyJob` calls it again for the claim instant; a ping straddling 00:00:00Z could pass the gate on one day and claim the next day's row. Harmless (claims the new day, once) and consistent with DEC-030's once-per-UTC-day rule.
